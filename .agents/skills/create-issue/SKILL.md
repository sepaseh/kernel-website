# Create an issue

Read [issue policy](../../rules/issues.md), [Git policy](../../rules/git.md)
and [safety](../../rules/safety.md).

1. Verify the repository, current evidence and existing issues for duplicates.
2. Draft one focused outcome with facts, expected behavior, impact and objective verification.
3. Exclude credentials, private records and production payloads.
4. Keep a draft local unless issue publication is explicitly authorized.
5. Verify actual labels/templates and the result of any authorized creation.
   Do not assign, comment elsewhere or start implementation without authorization.
