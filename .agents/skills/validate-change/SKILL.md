# Validate a change

Read changed owners, matching rules, [source marker](../../../.github/bootstrap-policy.json), [phase guide](../../../docs/bootstrap.md), [Contributing](../../../CONTRIBUTING.md) and [canonical manifest](../../validation.json). [Application integration](../../../docs/application.md) defines expanded acceptance when runnable composition is delivered; it does not register commands by itself.

- Behavior: begin with the smallest relevant owner test.
- TypeScript/TSX: include registered typecheck/lint; preserve both product/tooling projects.
- Imports/dependencies: run registered source-boundary checks and retain exact owner identity.
- Guidance: run structure/link/command consistency and affected governance tests, then formatting.
- Configuration: run its semantic policy and observable fixture tests.

Use commands actually registered for the source phase. Never omit required checks, import unpublished tooling, toggle a false source marker or substitute synthetic tests for actual browser acceptance. Runtime integration must register and execute all fifteen checks and current build/browser/CSP/visual evidence.

Before each authorized commit, push or PR handoff freshly install declared Node and pinned Python dependencies and pass the full profile on an isolated export of the exact proposed tree. Preserve measured production scope, thresholds and original failure logs; report source/tree, actual commands/results, failures/skips and unavailable evidence. Smaller development checks, hooks and primary-checkout results are insufficient.

Use owned disposable fixtures for [quality and delivery](../../../docs/testing.md). False-marker positive guard tests use explicitly marked synthetic roots, public values, injected engines and owned loopback listeners. Keep audit regressions in their measured unit owner. Core readiness precedes configuration, dependency, subprocess and network operations.

For [runners](../../../docs/runner-foundation.md), test inert imports, direct-child lifecycle, failure/cancellation and bounded analysis output with disposable Node children. For [browser tooling](../../../docs/browser-foundation.md), retain SDK identity, strict environment/launcher ownership, tooling typechecks and measured Node regressions. Real integration uses the pinned independently installed [API fixture](../../../docs/api-fixture.md), fresh state and verified browser; typed suites/callbacks/history are not execution evidence. Baseline changes require authorization and actual visual review.

Correct safe in-scope failures and rerun affected checks. Never weaken a gate or add suppressions. Ask only for a missing material decision, destructive/outside action or scope change not already authorized. Preserve existing user authorization. Report limits honestly; guidance checks do not measure host loading, semantic completeness or model performance.
