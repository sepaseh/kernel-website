# Commits

Do not commit without the user's approval. Inspect status and the complete
relevant diff, preserve unrelated changes and stage only the approved scope.
Never commit private data, dotenv, credentials, dependencies, reports or build output.

Before an authorized commit, pass [the complete exact-tree procedure](../../docs/validation.md).
A failure or unavailable required check blocks staging and committing.
Use a concise Conventional Commit subject under 72 characters.
Do not add AI co-author trailers unless requested.

Do not amend, rebase, force-push or rewrite published history without explicit
authorization. A commit request does not authorize a push, PR or merge.
Use [the commit skill](../skills/commit/SKILL.md) and [Git policy](git.md).
