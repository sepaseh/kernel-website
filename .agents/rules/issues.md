# Issues

Confirm the actual repository and issue, then read its evidence and acceptance
criteria. Verify current source before treating a reported symptom as established.
Separate observed facts, unknowns, scope and objective verification.

Keep one issue focused on one independently verifiable outcome. Check existing
issues for duplicates and actual labels/templates before using them.
Exclude credentials, private records and production payloads; use
[private security reporting](../../SECURITY.md) for vulnerabilities.

Draft locally unless publication is authorized. Creating, assigning, labeling,
commenting, closing or starting implementation needs authorization for that action.
Use [create-issue](../skills/create-issue/SKILL.md) or
[start-issue](../skills/start-issue/SKILL.md) for the requested workflow.
