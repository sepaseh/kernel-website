# Local website translations

All website messages are local source under src/i18n/catalog-data. The ten languages ar/de/en/es/fa/fr/it/pt/ru/tr each own exactly one code-named catalog in locales/<code>.ts. Each exports one flat Record<string, string>: no nested common/feature objects, dotted path keys, parallel sources or compatibility aliases. locales.ts registers supported catalog codes; erased types derive the complete key shape from en.ts.

Shared meanings have one canonical bare root key such as login or password. Feature-specific meanings use explicit lower-camel prefixes, such as authLoginTitle, accountEmail and accountEmailLabel; keep section headings distinct from input labels. Never merge meanings merely because text matches. Every key requires genuine nonempty translations in all ten languages with identical ICU {variable} placeholders and preserved newlines. No English spreads/fallback catalogs are allowed. Pure data imports only local erased types; engines/providers/validation stay outside catalog-data.

Published client components call useTranslations() at the root and use flat keys. Keep one translator per component when possible. Future server translation/request adapters and bootstrap-error pages must preserve the existing local catalog contracts; they are not part of this non-runnable phase. selectClientMessages uses explicit static root/auth/account key allowlists and requires strings; never ship the whole catalog, infer groups by prefix or import English runtime values to construct the lists. Update all-language scope tests with any intentional new client key.

Persisted public API settings choose the sole active language and its direction. Validate language.direction as ltr or rtl and use that exact API value, including when it differs from a local code-based expectation. Never derive or override direction from the catalog code. The website has no calendar display, so do not add an unused calendar or language-name registry. Preserve existing settings; malformed/unavailable/unsupported values are explicit errors. No visitor negotiation, language cookie or canonical language prefix. Future route integration must preserve the planned permanent /en and /fa aliases with queries; no routes or redirects execute in this phase.

Use the registered unit, typecheck and boundary checks from [validation.json](../validation.json); the real ICU/client-scope tests cover all ten catalogs and selected client messages. Browser and standalone test:i18n commands are not registered in this phase. Catalog changes are local; coordinate HTTP compatibility only when the wire protocol changes. See [localization](../../docs/localization.md).
