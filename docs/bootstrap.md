# Publication phases and source readiness

[English](bootstrap.md) · [فارسی](bootstrap.fa.md)

The [source policy](../.github/bootstrap-policy.json) is the authority for phase, readiness and exact inventory. The operations phase has `applicationReady:true`, 420 source files, 90 product modules, 38 source test files and three source test-support modules. It preserves runnable Next.js composition and adds six workflow sources, optional component-generator metadata, guarded Docker/Lighthouse runners and their operational wrappers/tests. Inventory size and the 100-entry PR limit are different counts; a true marker declares source completeness, not completed execution.

## Delivered foundation

[Forms](forms.md), [client UI](client-ui.md), [session](session.md), [document support](client-document.md), [fonts](fonts.md), [localization](localization.md) and [server boundaries](server-boundary.md) define published behavior. Real React/RTL, Radix, next-intl and next-themes use isolated jsdom and synthetic HTTP; framework/document navigation and motion retain their documented mocks. All product TS/TSX remains measured. Forms preserve session/generation/mount ownership, OTP destinations and scoped public/protected 401 feedback.

[Runner](runner-foundation.md) and [browser](browser-foundation.md) tooling has inert imports, readiness-first operations, explicit inputs and owned direct-child lifecycle. Product/tooling type checks and owned Node fixtures retain their separate contracts. The [API contract](api-fixture.md) requires immutable revision, clean source and independently installed dependencies, the published API entry, fresh owned state and strict launcher/worker settings. Actual build, independent API/browser/CSP execution and visual comparison are required application checks, independently of the Node owner tests.

[Delivery](deployment.md) and [operations](release-operations.md) own artifact/configuration/health/cleanup helpers and passive templates. Positive guard cases use owned synthetic ready roots, public values, fake engines or owned listeners. A test marker is data, not application acceptance. Core entries refuse a false source marker before configuration, dependency, network or artifact operations.

## Required evidence

[Canonical validation](../.agents/validation.json) registers fifteen full checks: snapshot, CI policy, guidance, audit, boundaries, types, lint, format, measured unit, measured governance, real font integrity, dead-code analysis, production build/bundle, browser/CSP and visual comparison. [Contributing](../CONTRIBUTING.md) requires fresh Node/pinned Python installation and full success on the exact isolated proposed tree before authorized commit/push/handoff. Every PR, including docs/drafts, runs the declared full profile without path filters.

Keep unit thresholds of 90% for four metrics, governance at 80% and measured font coverage minimum 80%. Reports remain generated: `coverage/unit/lcov.info`, `coverage/governance/lcov.info`, `coverage/fonts/coverage.xml`. Never fabricate them, exclude new source or weaken checks. Product and tooling TypeScript projects are both required. CI and scanner must preserve actual font installation/coverage sequencing.

## Application transition

[Application integration](application.md) maps the complete composition and acceptance contract. Framework adapters, CSS/configuration and their tests belong to the same exact source/import/coverage closure. The full profile requires real production build/bundle, browser journeys in both CSP modes and compatible visual comparison using the independently installed synthetic API, fresh state and verified browser. Record actual results and source identity; a separate candidate or historical image cannot validate this tree.

Before runnable merge, observe actual current-head build/e2e/visual jobs and make them protected through an explicitly authorized policy change. Preserve [ordinary protection](branch-protection.md), current-head approval and resolved conversations. A true marker, separate development candidate or historical baseline cannot replace execution.

## Guidance and publication

[Navigation](source-navigation.md) indexes published paths only. [Evaluation](comprehension-evaluation.md) separates static checks from measured source understanding and host discovery. Optional hooks, thin host adapters and assistant tools are not runtime dependencies or full gates. Dated QA and archived originals retain their historical dates/scope.

Keep one website PR open. After its actual authorized merge compare real main with the prepared base and rerun full acceptance for changed proposed bytes. Each PR changes at most 100 GitHub entries. Create authorized PRs ready for review. CodeRabbit requests require the [exact-head preflight](sonarqube.md#before-requesting-coderabbit), at least one hour since both latest request and substantive review, provider limits and no duplicate in flight. Publication alone authorizes no operations or production access.
