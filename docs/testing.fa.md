# آزمون وب‌سایت و شواهد

[English](testing.md) · [فارسی](testing.fa.md)

[فهرست مرجع](../.agents/validation.json) مالک دستورها و
[اعتبارسنجی](validation.fa.md) مالک محدوده و ترتیب است. مرحلهٔ
**delivery-tooling** فهرست دقیق ۳۰۳فایلی دارد و با applicationReady:false قابل اجرا
نیست. ۶۶ ماژول اجرایی، ۳۴ فایل آزمون سورس و سه ماژول پشتیبان آزمون سورس آن بدون
تغییر می‌مانند. چهار ابزار یکپارچه‌سازی حفظ‌شده با سه فایل آزمون مالک Node و هشت
ابزار تحویل با شش فایل آزمون مالک Node، نقطهٔ ورود برنامه یا راه‌انداز مرورگر، API
و Docker اضافه نمی‌کنند.

| لایه             | شاهد منتشرشده و محدودیت                                                                                                                                                                          |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| محصول محلی       | React/RTL و کتابخانهٔ پشتیبان واقعی، کد HTTP و نشست و Request/Response مصنوعی رفتار فرم و پشتیبانی را می‌سنجند. ناوبری فریم‌ورک و سند mock مستند دارد.                                           |
| کاتالوگ و فونت   | ده کاتالوگ تخت کامل، parse واقعی ICU و انتخاب صریح پیام؛ فایل واقعی فونت، بایت تولیدی، metadata و پوشش Python واقعی. نتیجهٔ شکل‌دهی و بارگذاری مرورگر از آن نتیجه نمی‌شود.                       |
| گردش‌کار و ابزار | محافظ مجموعهٔ فایل، import، CI و راهنما، هوک قابل‌انتقال و آزمون مالکِ محل صریح API، داده و بودجهٔ bundle و محیط کارایی و تصویر.                                                                 |
| قرارداد تحویل    | کپی و بسته‌بندی artifact، نگهبان آمادگی، تنظیم عمومی، هدف صریح سلامت، پاک‌سازی و اعتبارسنجی مقصد از فایل ساختگی متعلق به آزمون، عملیات تزریقی یا listener loopback متعلق به خود استفاده می‌کنند. |
| رگرسیون audit    | یازده مورد رگرسیون audit موجود در پوشش واحد اندازه‌گیری‌شدهٔ Vitest می‌مانند و به اجراکنندهٔ گردش‌کار Node منتقل نمی‌شوند.                                                                       |
| اتصال زمان اجرا  | صفحه، layout و CSS، سفر مرورگر، راه‌انداز API، مقایسهٔ تصویر واقعی، Lighthouse و استقرار به آینده موکول‌اند.                                                                                     |

مالکان یکپارچه‌سازی حفظ‌شده عبارت‌اند از [محل API](../scripts/api-repository.test.mjs)،
[ابزار کارایی](../scripts/website-performance.test.mjs) و
[ابزار تصویر](../scripts/visual-environment.test.mjs). آن‌ها fixture موقت
متعلق به خود دارند. manifest پروژه یا گراف ساخت مصنوعی، رفتار اعتبارسنجی
را می‌سنجد؛ API نصب‌شده، ساخت واقعی Next، تصویر یا اندازه‌گیری آزمایشگاهی نیست.

هشت ابزار تحویل مالک [سیاست مشترک فایل و آمادگی](../scripts/release-files.mjs)،
[آماده‌سازی standalone](../scripts/prepare-standalone.mjs)،
[بسته‌بندی](../scripts/package-release.mjs)،
[اعتبارسنجی تنظیمات](../scripts/validate-deployment-env.mjs)،
[رندر قالب عمومی](../scripts/render-deployment.mjs)،
[بررسی صریح سلامت](../scripts/healthcheck.mjs)،
[پاک‌سازی متعلق به اجرا](../scripts/docker-smoke-cleanup.mjs) و
[اعتبارسنجی مقصد](../scripts/validate-workflow-targets.mjs) هستند. شش فایل مالک Node
با پوشش واقعی عبارت‌اند از [سیاست فایل](../scripts/release-files.test.mjs)،
[آماده‌سازی](../scripts/prepare-standalone.test.mjs)،
[بسته‌بندی](../scripts/package-release.test.mjs)،
[قرارداد تنظیمات، سلامت و قالب](../scripts/deployment.test.mjs)،
[پاک‌سازی](../scripts/docker-smoke-cleanup.test.mjs) و
[قرارداد مقصد](../scripts/validate-workflow-targets.test.mjs). gate کامل یازده‌بررسی
هر نه فایل مالک Node یکپارچه‌سازی و تحویل را شامل می‌شود؛
[آزمون audit موجود](../scripts/run-audit.test.mjs) مالک واحد Vitest خود را حفظ می‌کند.

CLI اصلی تحویل پیش از عملیات marker عمومی بدون لینک آمادگی می‌خواهد و مرحلهٔ false
فعلی را رد می‌کند. آزمون کپی و بسته، ریشهٔ ساختگی متعلق به خود را صریحاً آماده
علامت می‌زند؛ این رفتار فایل را می‌سنجد و برنامهٔ غایب را تأیید نمی‌کند. آزمون تنظیم
مقدار عمومی تزریق می‌کند، آزمون سلامت listener loopback متعلق به خود دارد و آزمون
پاک‌سازی callback ساختگی Docker و Compose می‌دهد. dotenv واقعی، engine، سرویس TLS،
مرورگر یا محیط اپراتور به کار نمی‌رود. [تحویل](deployment.fa.md) و
[عملیات](release-operations.fa.md) مرجع غیرفعال و پذیرش بعدی را شرح می‌دهند.

حل‌کنندهٔ محل API به KERNEL_SYNTHETIC_ENV=1 و KERNEL_API_DIRECTORY مطلق و
صریح نیاز دارد. نشانه‌های پروژهٔ منتخب را بدون fallback همسایه بررسی می‌کند؛
نصب، راه‌اندازی یا آمادگی fixture در revision تغییرناپذیر را تأیید نمی‌کند.
fixture مستقل نصب‌شدهٔ آینده پیش از شاهد زمان اجرا به revision و قرارداد
تأییدشدهٔ خودش نیاز دارد. سرویس توسعهٔ موجود و دادهٔ اپراتور fixture نیستند.

دستور، محدوده و revision دقیق سورس، نخستین شکست، نتیجه، شکست و skip، پوشش
و پاک‌سازی را ثبت کنید. بررسی محلی، بررسی سرویس میزبانی‌شده، ارزیابی دستی و
سابقهٔ تاریخ‌دار ثبت‌های متفاوت‌اند. [پایداری آزمون](test-reliability.fa.md)
را رعایت کنید. پیش از انتشار قابل اجرا، بررسی واقعی build، مرورگر، هر دو
حالت CSP و تصویر سازگار را اضافه و موفقیتشان را مشاهده کنید. آزمون محلی SSR،
cookie مرورگر، دسترس‌پذیری کامل، استقرار، OTP واقعی یا کارایی میدانی را ثابت نمی‌کند.
