# ابزار CSP و پذیرش زمان اجرا

[English](website-csp.md) · [فارسی](website-csp.fa.md)

[helper خالص CSP](../src/shared/security/csp.ts) و
[آزمون مالک](../src/shared/security/csp.test.ts) دادهٔ سیاست را تعریف می‌کنند.
[هماهنگ‌کنندهٔ محافظت‌شدهٔ CSP](../scripts/test-csp-report-only.mjs) و سناریوی
نوشته‌شدهٔ مرورگر نیز موجودند. با [نشانگر انتشار](../.github/bootstrap-policy.json)
false، اتصال proxy درخواست، nonce و layout، هدر واقعی CSP یا اعمال مرورگر
اثبات نمی‌شود. [قرارداد برنامه](application.fa.md) این اتصال و شاهد واقعی هر
دو حالت را لازم دارد.

## قرارداد پیاده‌شده

readWebsiteCspMode مقدار report-only یا enforce را می‌پذیرد و مقدار غایب را
report-only می‌گیرد. createWebsiteCsp، nonce ورودی را می‌سنجد و سیاست را
می‌سازد؛ آرگومان development مجازهای توسعه را کنترل می‌کند. parse حالت و
ساخت سیاست جدا هستند: انتخاب هدر گزارش‌دهنده یا اعمال‌کننده متعلق به اتصال
آداپتر درخواست برنامه است. مشاهدهٔ report-only را مسدودکردن تخلف معرفی نکنید.

سیاست، عنصر script و style را با nonce ورودی و قواعد هم‌مبدأ محدود می‌کند.
ویژگی style عمداً مجاز inline را برای سازگاری React/Motion نگه می‌دارد؛
این اجازهٔ script دلخواه inline نیست. فقط توسعه، unsafe-eval و WebSocket
را مجاز می‌کند. predicate خالص مسیر سند، API، static، فونت و metadata را
تفکیک می‌کند، اما نصب matcher فریم‌ورک یا خط پاسخ را ثابت نمی‌کند.

helper تصادفی تولید نمی‌کند، هدر nonce فراخواننده را حذف نمی‌کند، هدر نمی‌گذارد،
HTML نمایش نمی‌دهد و رفتار cache را اعمال نمی‌کند.
[ارسال API](server-boundary.fa.md) جداگانه از مسیر فهرست‌شده، مبدأ تغییر،
cookie و پاسخ خصوصی no-store محافظت می‌کند. [JSON-LD](client-document.fa.md)
همچنان خروجی escapeشده می‌خواهد؛ CSP جای مجوز API یا نمایش امن نیست.

## پذیرش اتصال قابل اجرا

برای هر سند nonce غیرقابل‌پیش‌بینی بسازید، جعل فراخواننده را رد و همان مقدار
قابل اعتماد را به خروجی فریم‌ورک، پوسته و JSON-LD بدهید. HTML اولیه و رفتار
پس از hydration را بررسی کنید؛ پاک‌کردن nonce زندهٔ یک کتابخانه ثابت نمی‌کند
script اولیه بی‌محافظ بوده است. HTML خصوصی دارای nonce وارد cache مشترک
نشود؛ مرز واقعی سند، API، static، metadata و سند مفقود آزموده شود.

برای اجرای جداگانهٔ مرورگر در enforce و report-only، همان ساخت production
تأییدشده را به‌کار ببرید. آزمون منفی script و style به تزریق واقعی پاسخ و
کنترل قابل اعتماد نیاز دارد؛ ارزیابی debugger به‌تنهایی شاهد اجرای CSP نیست.
هدر واقعی، یکتایی، رد جعل، پوسته و حرکت، cache و شکست را ثبت کنید. اتصال
gateway و TLS و هر مبدأ یا جمع‌آورندهٔ دوردست به تغییر مجاز و آزمون خودش
نیاز دارد. پذیرش محلی برنامه، شاهد لبهٔ مستقر نیست.

[آزمون](testing.fa.md) و [اعتبارسنجی](validation.fa.md) را رعایت کنید. رفتار
سورس و واحد، رفتار واقعی مرورگر و شاهد امنیت استقرار نتایج متفاوت‌اند.
