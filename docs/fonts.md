# Local font integrity

The [Vazirmatn 33.003 variable source](../font-source/vazirmatn-variable.woff2)
supplies Latin/basic, Arabic/Persian and extended subsets. Unsupported glyphs,
including Cyrillic, use the CSS fallback stack. [SIL Open Font License](../public/fonts/OFL.txt)

The [font manifest](../src/shared/fonts/manifest.json) records hashes, sizes,
CSS ranges, variable axes and tool versions. CSS ranges assign each source
codepoint once. Supporting spaces can appear in several binaries for shaping.
Each subset preserves weights 100–900, source copyright and license names, and
the standard fontTools layout features.

## Required verification

Follow [validation setup](validation.md#install-and-run-all-checks) to install
[the hash-locked font tooling](../font-source/requirements.txt) in a disposable
Python 3.14.4 environment. The governance CI job installs those same wheels
and publishes the measured report for the scanner. For a focused font change, run:

```sh
npm run check:fonts
```

The command passes when regenerated bytes match the maintained assets and
measured Python coverage meets its threshold. If it fails, check the Python
version and locked packages before investigating a stale binary.

`--check` regenerates all three WOFF2 buffers, CSS and JSON in memory and compares
them byte for byte with the maintained files. It verifies the cmap partition,
weight axes and license metadata. [Subset generator](../scripts/subset-website-fonts.py)

Node owner tests independently check source/output hashes and bytes, distributed license presence, every CSS range for disjoint/full assignments, budgets and preload selection for all ten locales. The preload helper always selects Latin and adds Arabic only for fa/ar. This is a selection policy, not measured browser loading.

Measured Python branch/line coverage is generated at coverage/governance/font-coverage.xml and imported into Sonar; TypeScript and governance reports remain separate. No source/security/coverage exclusion is added. Generated manifest/CSS have a narrow formatting ignore so the real generator's exact output remains deterministic.

## Regenerate intentional font changes

After an authorized font change, regenerate with the same pinned Python tools:

```sh
python scripts/subset-website-fonts.py
npm run check:fonts
```

Review the regenerated outputs and use the [full gate](validation.md) before
publication. Keep the complete source outside `public/` and preload only the
subsets selected by the [font preload helper](../src/shared/fonts/preloads.ts).

Binary checks do not establish browser shaping or visual quality. The
[browser suites](browser-foundation.md) exercise EN/FA/TR resource loading, mixed
text, reduced motion and JavaScript-disabled content; their actual results must
come from the current tree. Review rendered glyphs against the full source when
changing subsets and use [visual comparison](visual-regression.md) for layout.
Field font performance needs its own observed evidence.
