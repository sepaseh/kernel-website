# مرحلهٔ ترجمه

[English](bootstrap.md) · [فارسی](bootstrap.fa.md)

این مرحله بیست‌وپنج فایل سورس دارد: قراردادها، ابزار فرم، اعتبارسنجی نشانی API،
خواندن زبان تنظیمات عمومی با مرجعیت API، ده کاتالوگ تخت با ۱۰۷ کلید، نوع
حذف‌شوندهٔ کلید و فهرست صریح بارگذار تنبل، همراه سه فایل تست سورس.
[فهرست دقیق](../.github/bootstrap-policy.json) مقدار `applicationReady:false`
را الزامی می‌کند. [ترجمه‌ها](localization.fa.md) مالکیت کاتالوگ و سیاست زبان
را توضیح می‌دهد. برنامهٔ Next.js، نمایش واقعی ICU، سفر مرورگر، استقرار یا
وابستگی زمان اجرا در این مرحله وجود ندارد.

پس از `npm ci`، دستور `npm run validate -- full` را اجرا کنید.
[فهرست مرجع](../.agents/validation.json) نه بررسی الزامی دارد: مجموعهٔ دقیق،
سیاست CI، audit، import بسته، نوع‌ها، lint، قالب‌بندی، تست واحد با پوشش و تست گردش‌کار
با پوشش. پیش از commit، push یا تحویل PR مجاز، تمام مرحلهٔ فعلی را روی مجموعهٔ
دقیق جداگانه اجرا کنید؛ سورس حذف‌شده از این مجموعه در پوشهٔ اصلی شاهد نیست.

هر PR، از جمله پیش‌نویس، همین دستور کامل مرجع را بدون فیلتر فایل‌های تغییرکرده
اجرا می‌کند. اجراکننده پیش از اجرا، کل برنامهٔ انتخاب‌شده را اعتبارسنجی می‌کند:
شناسهٔ بررسی یا عضو پروفایل تکراری، بررسی ناشناخته، بررسی الزامی جامانده و مورد
دستی یا توصیه‌ای در `full` باعث شکست می‌شود. CI فهرست دومی از دستورهای مرحله
ندارد. پروفایل محدود برای توسعه باقی است، اما جای گیت کامل PR را نمی‌گیرد.

محافظ سیاست CI، فایل YAML را با کلیدهای یکتا می‌خواند و رویداد PR، job الزامی،
پوشهٔ ریشه و اجرای بی‌شرط نصب و گیت کامل را بررسی می‌کند. فیلتر مسیر یا شاخه،
شرط پیش‌نویس، نادیده‌گرفتن شکست و دستور جامانده یا جابه‌جا باعث شکست اعتبارسنجی
می‌شود. تمام بررسی‌های الزامی فعلی متعلق به `check` هستند؛ jobهای آیندهٔ build،
e2e و visual به انتقال صریح سیاست نیاز دارند تا بررسی مخصوص Windows بی‌سروصدا
روی Linux اجرا نشود.

پوشش واحد باید برای statement، شاخه، تابع و خط به ۹۰٪ برسد. پوشش گردش‌کار برای
خط، تابع و شاخه، بدون فایل تست، حداقل ۸۰٪ است. گزارش‌ها از اجرای واقعی در
`coverage/unit/lcov.info` و `coverage/governance/lcov.info` ساخته می‌شوند؛
آن‌ها را commit یا جعل نکنید و پوشش وب‌سایت کامل ننامید.

فهرست، فایل اضافه یا مفقود، مسیر خصوصی و لینک نمادین را رد و پیوندهای محلی
مستندات را بررسی می‌کند. پوشه‌های معمول `node_modules` و `coverage` در
ریشه برای خروجی مجازند. سقف ۱۰۰ فایل برای فایل‌های تغییرکردهٔ هر PR است و
تعداد کل فهرست را محدود نمی‌کند.

[CI](../.github/workflows/ci.yml) تمام مرحله و بررسی اندازهٔ PR با دسترسی
فقط‌خواندنی عادی را اجرا می‌کند. [محافظ target](../.github/workflows/pr-policy.yml)
فقط checkout ثابت `github.workflow_sha` را با دسترسی فقط‌خواندنی اجرا می‌کند.
در این رویداد دارای دسترسی، کد head یا مبنای بازبینی‌نشده را اجرا نکنید.
محافظ اندازه، شمارش بیش از ۱۰۰ فایل را پیش از دریافت فهرست رد می‌کند. PR مجاز
در یک صفحهٔ کامل جا می‌گیرد؛ صفحه‌بندی غیرمنتظره، اطلاعات ناقص فایل و تغییر
head، base یا تعداد فایل باعث شکست می‌شود.

از CI، CodeRabbit و Sonar بومی، یک بازبینی تأییدشده و حل گفتگوها استفاده کنید.
بازبینی خودکار CodeRabbit خاموش است؛ فقط پس از تأمین [تمام پیش‌شرط‌ها](sonarqube.fa.md#پیش-از-درخواست-بازبینی-coderabbit) برای head فعلی، دستی درخواست بازبینی کنید. موفقیت تمام بررسی‌های الزامی غیر از CodeRabbit و صفر بودن یافتهٔ OPEN یا حل‌نشده در تمام شدت‌ها الزامی است؛ مجموعهٔ مصوب بررسی مرحله ملاک است. پس از تغییر head دوباره بررسی کنید، سهمیه را رعایت و درخواست در حال اجرا را تکرار نکنید. [مشارکت](../CONTRIBUTING.fa.md)،
[حفاظت شاخه](branch-protection.fa.md) و [Sonar](sonarqube.fa.md) را ببینید.

طبق سیاست انتشار غیرقابل اجرا، jobهای build و e2e و visual
برنامه اکنون الزامی نیستند. چهار بررسی بومی در [حفاظت شاخه](branch-protection.fa.md)
آمده‌اند؛ فهرست بسته و applicationReady:false تغییر نکرده‌اند. job ساختگی یا
بررسی الزامی اجرا‌نشده استفاده نمی‌شود. پیش از ادغام هر برنامهٔ قابل اجرا،
build واقعی رابط، HTTP و احراز هویت، مرورگر و CSP، دسترس‌پذیری و تصاویر
بازبینی‌شده را با fixture مصنوعی API که مستقلاً منتشر شده اضافه کنید؛ موفقیت
jobهای واقعی build و e2e و visual را مشاهده و آن‌ها را الزامی کنید و اعتبارسنجی
کامل مرجع را گسترش دهید. تمام حفاظت‌های دیگر حفظ شوند.

برنامهٔ کامل وب‌سایت پانزده بررسی الزامی دارد. سورس و fixture واقعی آن‌ها باید
با PRهای متمرکز منتشر شود تا این انتشار غیرقابل اجرا به برنامهٔ قابل اجرا تبدیل
شود. پس از افزودن این بررسی‌ها، تمام گیت برنامه در هر PR و مستقل از مسیرهای
تغییرکرده اجرا می‌شود؛ سقف ۱۰۰ فایل PR مستقل از دامنهٔ تست‌ها است.
