# پشتیبانی SEO و پذیرش برنامه

[English](seo.md) · [فارسی](seo.fa.md)

[ابزار SEO](../src/shared/seo) مالک اعتبارسنجی مبدأ، metadata صفحه و سریال‌سازی
امن دادهٔ ساختاریافته است. [نشانگر انتشار](../.github/bootstrap-policy.json)
محدودهٔ واقعاً تحویل‌شده را مشخص می‌کند. در حالت `applicationReady:false`، آزمون
helper و سناریوی نوشته‌شدهٔ مرورگر، نمایش metadata، پاسخ robots و sitemap و
تصویر اجتماعی یا وب‌سایت ایندکس‌شده را ثابت نمی‌کنند.
[قرارداد برنامه](application.fa.md) پیش از پذیرش قابل اجرا، شاهد واقعی مسیر و
HTML و مرورگر را لازم دارد. این راهنما تأیید دامنه، بررسی Search Console، ارسال
sitemap یا تغییر ایندکس production را ثبت نمی‌کند.

## پیکربندی و حریم خصوصی

`API_BASE_URL` اتصال server-to-server به API را تعیین می‌کند. `WEBSITE_URL`
مبدأ عمومی وب‌سایت برای canonical و اشتراک‌گذاری است؛ آن را از Host ورودی حدس
نزنید و مبدأ API را جایگزین نکنید. `readSeoConfig` یک مبدأ کامل HTTP(S) بدون
اعتبارنامه، مسیر غیرریشه، query، fragment، فاصله یا نویسهٔ کنترلی می‌پذیرد.
اسلش پایانی ریشه مجاز است. HTTP فقط برای loopback با ایندکس خاموش مجاز است.

`WEBSITE_INDEXING_ENABLED` فقط مقدار دقیق `true` یا `false` دارد؛ نبود آن یعنی
false. مقدارهایی مانند `1`، `TRUE` و رشتهٔ خالی خطا دارند. URL غایب یا خالی در
حالت خاموش مجاز است و canonical و دادهٔ ساختاریافتهٔ وابسته به URL حذف می‌شوند.
درخواست ایندکس به مبدأ HTTPS غیرloopback نیاز دارد و فقط با
`NODE_ENV=production` فعال می‌شود. حالت production به‌تنهایی ایندکس را روشن
نمی‌کند. محیط محلی یا preview و staging عمومی، ایندکس را خاموش نگه می‌دارند.
تغییر production فقط پس از پذیرش دامنه، محتوا، دسترسی و استقرار انجام شود؛
انتشار این راهنما مجوز چنین عملیاتی نیست.

در تست، پیکربندی مصنوعی صریح بدهید. برای بررسی SEO، dotenv یا اعتبارنامهٔ واقعی
را نخوانید و تغییر ندهید. پیکربندی استقرار، بارگذاری و رفتار راه‌اندازی مجدد
متعلق به runtime واقعی و [قرارداد تحویل](deployment.fa.md) است؛ helper خالص
فایلی بارگذاری یا سرویسی restart نمی‌کند. این helperهای سرور به مقدار
`NEXT_PUBLIC_*` نیاز ندارند.

noindex حضور در جست‌وجو را کنترل می‌کند، نه محرمانگی را. ورود و مجوز API باید
از محتوای خصوصی محافظت کنند. robots خزیدن را کنترل می‌کند؛ منع دریافت صفحه ممکن
است مانع دیده‌شدن noindex شود. پذیرش برنامه باید HTML و هدر پاسخ، از جمله
`X-Robots-Tag` لبه، را بسنجد و نتیجهٔ helper را پاسخ تحویل‌شده فرض نکند.

## قرارداد صفحه و زبان

`createPageMetadata` عنوان کامل، توضیح، pathname مطلق و `index:false` اختیاری
می‌گیرد. اسلش پایانی مسیر را نرمال و scheme، query، fragment، پیمایش و جداکننده
یا نویسهٔ کنترلی کدگذاری‌شده را رد می‌کند. عنوان مطلق، canonical همان صفحه در
صورت تنظیم، robots و metadata اشتراک‌گذاری می‌دهد. پرچم سراسری نمی‌تواند
`index:false` را لغو کند. هنگام وجود مبدأ، helper مسیر `/social-image` با اندازهٔ
۱۲۰۰×۶۳۰ را توصیف می‌کند؛ آن مسیر را پیاده نمی‌کند و وجود پاسخ را ثابت نمی‌کند.

برنامهٔ اولیهٔ پذیرفته‌شده، `/` را صفحهٔ محتوایی عمومی دارد. ورود، ثبت‌نام،
بازیابی، حساب و صفحهٔ خطا noindex و بیرون sitemap می‌مانند. صفحهٔ عمومی تازه
pathname canonical خودش را می‌خواهد؛ قرار دادن `/` در layout ریشه برای همهٔ
صفحات، محتوای متفاوت را نادرست معرفی می‌کند. query رهگیری و fragment صفحهٔ مستقل
نیستند. لینک داخلی، redirect، canonical و sitemap یک مقصد عمومی را نشان دهند.

API مستقل، تنها زبان فعال و جهت دقیق را انتخاب می‌کند. هر ده
[کاتالوگ تخت محلی](localization.fa.md) کامل می‌مانند و متن سایت و metadata بدون
مذاکرهٔ بازدیدکننده از کاتالوگ منتخب می‌آیند. طراحی پذیرفته‌شدهٔ URL بدون پیشوند،
`/en` و `/fa` را alias دائمی قدیمی با حفظ query می‌داند، نه نسخهٔ زبانی مستقل
قابل ایندکس. آن‌ها را در sitemap یا hreflang معرفی نکنید. URL هم‌زمانِ مستقل
برای زبان‌ها به تصمیم تازهٔ زبان، cache و metadata نیاز دارد.

اتصال ریشه و درخواست باید HTML اولیه، lang/dir، canonical، metadata، redirect
و status واقعی را، از جمله با JavaScript خاموش و user agent خزنده، بررسی کند.
وجود مؤلفهٔ صفحهٔ مفقود یا noindex به‌تنهایی پس از آغاز streaming وضعیت 404 را
ثابت نمی‌کند. هر صفحهٔ غایب یا خطا را به پاسخ موفق خانه تبدیل نکنید. پیش از
ادعای معنای الزامی 404/410، مستندات Next.js نصب‌شده و مرز پاسخ را بررسی کنید.

## افزودن محتوای عمومی

ابتدا صفحهٔ مفید، مخاطب و محتوای واقعی را مشخص کنید. مسیر در موجودی برنامه و
نمایش کنار مالک معنایی قابلیت باشد. `createPageMetadata` را با مسیر همان صفحه
و کلید تخت کامل در تمام زبان‌ها استفاده کنید. مثال قدیمی namespace تودرتوی
`Metadata` را کپی نکنید و دستور مستقل ترجمهٔ ثبت‌نشده نسازید.

محتوای عمومی API از مرز سرور دریافت شود و دادهٔ منتشرنشده یا شخصی وارد cache
مشترک نشود. محتوای غایب و منتشرنشده، metadata، sitemap، preview و لغو انتشار
باید هم‌خوان باشند. پنهان‌کردن لینک، حفاظت دسترسی پیش‌نویس نیست. لینک داخلی قابل
کشف و فقط URL عمومی canonical در sitemap اضافه کنید. `lastModified` از زمان
واقعی تغییر مهم محتوا بیاید؛ اگر چنین منبعی نیست حذفش کنید و در هر درخواست
زمان تازه تولید نکنید.

سیاست اولیهٔ پذیرفته‌شدهٔ robots، دریافت صفحه برای دیدن noindex را مجاز و
`/api/` را مستثنی می‌کند؛ sitemap اولیه هنگام خاموش‌بودن ایندکس خالی و در حالت
روشن فقط شامل خانهٔ عمومی است. این‌ها الزام برنامه‌اند، نه خروجی اجراشدهٔ این
پیش‌نیاز. با تغییر مسیر دوباره بررسی شوند.

`createWebsiteJsonLd` دادهٔ سادهٔ `WebSite` را از نام واقعی، توضیح، زبان فعال و
مبدأ تنظیم‌شده می‌سازد و بدون مبدأ شیئی نمی‌دهد. `serializeJsonLd` پس از
سریال‌سازی JSON هر `<` را escape و خروجی undefined غیرقابل‌سریال‌سازی را رد
می‌کند. هنگام نمایش برنامه، خروجی امن و nonce معتبر درخواست را حفظ کنید.
اطلاعات تماس، review، امتیاز، نویسنده، تاریخ یا SearchAction برای محتوا و قابلیت
ناموجود نسازید. دادهٔ ساختاریافتهٔ معتبر، نمایش ویژه یا رتبه را ثابت نمی‌کند.

رسانهٔ واقعی با URL عمومی پایدار، متن جایگزین توصیفی، اندازهٔ صریح و فرمت مناسب
تهیه کنید. دارایی خصوصی، خصوصی بماند. کارت برند اشتراک‌گذاری شاهد تصویر محصول یا
لوگوی واقعی نیست. اگر ویدئو محتوای اصلی شد، صفحهٔ واقعاً مرئی، thumbnail قابل
دریافت، عنوان و توضیح و اطلاعات درست انتشار و مدت، همراه caption و متن قابل
استفاده لازم است. ویدئوی تزئینی صفحهٔ تماشای مستقل را ثابت نمی‌کند.

## اعتبارسنجی و شاهد انتشار عمومی

بررسی را از [manifest مرجع](../.agents/validation.json) و
[مشارکت](../CONTRIBUTING.fa.md) انتخاب کنید. تست مالک config و metadata و دادهٔ
ساختاریافته، رفتار واقعی helper را با ورودی مصنوعی می‌سنجد. سناریوی نوشته‌شدهٔ
SEO مرورگر همچنان موجودی دقیق قابل اجرا، ساخت واقعی و تأییدشدهٔ production و
[API مصنوعی پین‌شده](api-fixture.fa.md) می‌خواهد. فعال‌سازی برنامه همهٔ تست‌های
helper و هر پانزده بررسی و job محافظت‌شدهٔ build/e2e/visual را حفظ می‌کند.
گزارش قدیمی، بررسی سورس یا دستور ساختگی را جایگزین نکنید.

سورس و build، تنظیم، نسخه، HTML اولیه و status، canonical، robots و sitemap،
noindex حالت خصوصی و خطا، پاسخ تصویر اجتماعی و JSON-LD parseشده را ثبت کنید.
تنظیم دردسترس‌نبوده و خطای امن را بسنجید. تیتر معنادار، لینک قابل استفاده، رفتار
صفحه‌کلید، کنتراست، حالت موبایل و کاهش حرکت و
[کارایی اندازه‌گیری‌شده](website-performance.fa.md) بررسی شود؛ metadata کامل
یا امتیاز آزمایشگاهی رتبه را تضمین نمی‌کند.
[دسترس‌پذیری](accessibility.fa.md) شاهد خودش را دارد.

تغییر Search Console و DNS به مالک دامنهٔ جداگانه مجاز نیاز دارد. پس از انتشار
عمومی مصوب، مالکیت با مقدار واقعی ارائه‌دهنده تأیید، sitemap همان مبدأ ارسال و
پاسخ عمومی واقعی بررسی شود. ایندکس، canonical منتخب، خطای خزیدن و معیار میدانی
در صورت وجود داده پایش شوند. ارسال sitemap ایندکس را تضمین نمی‌کند و تغییر فوری
نیست. تغییر دامنه، URL یا سیاست زبان به برنامهٔ انتقال و redirect نیاز دارد.
محتوای مفید، هویت و تماس واقعی، رسانهٔ تأییدشده و پایش مداوم مسئولیت محصول و
اپراتور می‌مانند.

مرجع: [noindex در Google](https://developers.google.com/search/docs/crawling-indexing/block-indexing)،
[canonical](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)،
[سایت‌های دارای نسخهٔ زبانی](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites)،
[sitemap](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)
و [سیاست دادهٔ ساختاریافته](https://developers.google.com/search/docs/appearance/structured-data/sd-policies).
