Core delivery CLIs require the unlinked public readiness marker before operations
and refuse this false phase. Copy/package tests explicitly mark owned synthetic
roots ready; that tests file behavior, not the missing application. Configuration
tests inject public values, health tests use owned loopback listeners, and cleanup
tests inject fake Docker/Compose callbacks. No real dotenv, engine, TLS service,
browser or operator environment is used. [Delivery](deployment.md) and
[operations](release-operations.md) describe the inert references and later acceptance.

The API resolver requires KERNEL_SYNTHETIC_ENV=1 and an explicitly selected absolute
KERNEL_API_DIRECTORY. It validates selected project markers without a sibling
fallback. It does not install, launch or attest an immutable fixture's readiness.
A future independently installed API fixture needs its own verified revision and
contract before runtime evidence. Existing developer services and operator state
are never fixtures.

Record command, exact source scope/revision, first failure, result, failures/skips,
coverage and cleanup. Local checks, hosted provider checks, manual assessment and
dated history are different records. Follow [test reliability](test-reliability.md).
Before runnable publication, add and observe genuine build, browser, both CSP-mode
and compatible visual checks. Local tests do not establish SSR, browser cookies,
complete accessibility, deployment, production OTP or field performance.

The [runner foundation](runner-foundation.md) adds six Node modules and six measured Node owner-test files for explicit inputs, direct-child lifecycle, standalone/API fixture launching and bounded analysis output. The website, API, server and analyzer entry operations read the public readiness marker first and refuses this snapshot with applicationReady:false. Imports do not load dotenv, mutate the environment or launch a service. Tests run owned synthetic Node programs, including failure and cancellation; they do not execute a real Next.js build/start, independent API, browser, Docker engine or lab analysis. The unchanged eleven-check gate measures the new tooling without weakening thresholds or excluding source. The [browser foundation](browser-foundation.md) now adds typed authored suites, readiness-first Playwright configuration and visual/CSP orchestration. Four Node owner files measure guards and injected behavior; browser binaries, independent APIs and real browser/visual execution remain deferred.
