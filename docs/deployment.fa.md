# آماده‌سازی تحویل و پذیرش اجرای واقعی

[English](deployment.md) · [فارسی](deployment.fa.md)

مرحلهٔ **delivery-tooling** ابزارهای محلی فایل و پیکربندی و مرجع‌های غیرفعال
استقرار را منتشر می‌کند. مقدار `applicationReady:false` الزامی می‌ماند. وب‌سایت
هنوز مسیر برنامه، چیدمان ریشه، خط پردازش CSS یا سرور قابل اجرا ندارد. این مرحله
هیچ build برنامه، API، مرورگر، موتور Docker یا مقصد مستقر را اجرا یا تأیید نمی‌کند.

## قرارداد ابزارهای منتشرشده

[آماده‌سازی standalone](../scripts/prepare-standalone.mjs)،
[بسته‌بند نسخه](../scripts/package-release.mjs) و
[سیاست مشترک فایل](../scripts/release-files.mjs) روی ورودی محلی صریح کار می‌کنند.
آزمون‌های مالک از درخت build ساختگی و موقت استفاده می‌کنند. کپی fixture شبیه سرور
و ثبت فرادادهٔ نسخه، رفتار فایل را ثابت می‌کند؛ نه تولید سرور سالم به‌وسیلهٔ
Next.js یا کامل و قابل استفاده بودن وابستگی‌های همراه. شناسه و مقصد نسخه انحصاری
است و نسخهٔ موجود محل بازنویسی آزمایشی نیست. CLI اصلی تحویل پیش از خواندن محیط، شبکه
یا کپی artifact، سیاست عمومی بدون لینک با schema نسخهٔ ۱ و applicationReady برابر
true می‌خواهد. سیاست false فعلی آن را رد می‌کند؛ فقط ریشهٔ ساختگی متعلق به آزمون
برای بررسی قرارداد آمادگی اعلام می‌کند و پرچم دورزدن وجود ندارد. حذف رده‌های فایل ممنوع نیز نبود رمز
در محتوای دلخواه فایل مجاز را ثابت نمی‌کند.

[اعتبارسنج پیکربندی](../scripts/validate-deployment-env.mjs) تنظیم صریح وب‌سایت را
می‌سنجد و [رندر قالب](../scripts/render-deployment.mjs) فیلد عمومی معتبر را بدون
نصب سرویس جایگزین می‌کند. [ابزار سلامت](../scripts/healthcheck.mjs) مقصد صریح
می‌خواهد؛ import آن مجوز یا اجرای درخواست شبکه نیست. آزمون‌ها پاسخ ساختگی یا
شنوندهٔ loopback متعلق به آزمون دارند و به API موجود متصل نمی‌شوند. فایل‌های نمونهٔ
عمومی فقط جای‌نگهدار سورس‌اند؛ محیط واقعی اپراتور، کلید و داده بیرون کد و artifact
می‌ماند.

مرجع‌های [Docker](../deploy/docker/README.fa.md) و
[native](../deploy/native/README.fa.md) مرز پیشنهادی سرویس و درگاه را شرح می‌دهند و
راهنمای اجرای این snapshot نیستند. پیش از برنامه‌ریزی فعال‌سازی بعدی،
[عملیات](release-operations.fa.md)، [staging](staging.fa.md) و
[مدل تهدید](security/threat-model.fa.md) را بخوانید.

## پذیرش پیش از استقرار قابل اجرا

تغییر مجاز بعدی باید ترکیب واقعی فریم‌ورک و build تولید تأییدشده را تحویل دهد،
fixture ساختگی API مستقل را نصب کند و تمام gateهای الزامی برنامه، build، مرورگر و
تصویر را معرفی کند. سورس دقیق، ابزار، پلتفرم، هش artifact و نتیجهٔ واقعی ثبت شود.
[پروفایل اعتبارسنجی](validation.fa.md) یازده‌بررسی فعلی همچنان الزامی است؛ آزمون
ابزار محلی جای بررسی اجرای آینده را نمی‌گیرد.

پیش از فعال‌سازی اپراتور، میزبان و forwarding مورداعتماد، کوکی هم‌مبدأ API، تنظیم
زمان درخواست، CSP و cache، دارایی و فونت، مقصد صریح سلامت، مالکیت گواهی و هویت
غیرقابل‌بازنویسی نسخه بررسی شود. بازگشت با artifact و تنظیم مطابق قبلی و cache
نوشتنی جدا برای هر نسخه تأیید شود. مجوز، ماندگاری، migration و بازیابی داده مسئولیت
مالک API مستقل می‌ماند. انتشار این ابزار و راهنما هیچ استقرار، بازگشت یا تغییر
زیرساختی انجام نمی‌دهد.
