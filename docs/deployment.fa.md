# آماده‌سازی تحویل و پذیرش اجرای واقعی

[English](deployment.md) · [فارسی](deployment.fa.md)

مرحلهٔ application ترکیب قابل اجرای Next.js، CSS و فرمان build/start را با `applicationReady:true` فراهم می‌کند. ابزار تحویل محلی و مرجع‌های استقرار در پایین پذیرش عملیاتی جداگانهٔ خود را حفظ می‌کنند. دروازهٔ کامل برنامه برای سورس آن لازم است، ولی موتور Docker، سرویس Linux نصب‌شده، گواهی، نسخهٔ انتشار یا مقصد مستقر را اجرا یا تأیید نمی‌کند.

## قرارداد ابزارهای منتشرشده

[آماده‌سازی standalone](../scripts/prepare-standalone.mjs)، [بسته‌بند انتشار](../scripts/package-release.mjs) و [سیاست فایل](../scripts/release-files.mjs) مشترک با ورودی محلی صریح کار می‌کنند. آزمون مالک درخت ساخت مصنوعی دورریختنی دارد؛ کپی fixture شبیه سرور فقط رفتار فایل را می‌سنجد و artifact کامل و قابل اجرا نیست. CLI اصلی پیش از خواندن محیط، شبکه یا عملیات فایل، سیاست آمادگی schema1 عادی و بدون پیوند با applicationReady true می‌خواهد؛ سیاست false یا نامعتبر همچنان بدون راه دورزدن رد می‌شود. نشانگر true مجوز انتشار نسخه یا استقرار نیست. شناسه و مقصد نسخه انحصاری می‌مانند؛ نسخهٔ موجود محل آزمایش و بازنویسی نیست. فیلتر ردهٔ فایل، نبود راز در محتوای دلخواه مجاز را ثابت نمی‌کند.

[اعتبارسنج پیکربندی](../scripts/validate-deployment-env.mjs) تنظیم صریح وب‌سایت را
می‌سنجد و [رندر قالب](../scripts/render-deployment.mjs) فیلد عمومی معتبر را بدون
نصب سرویس جایگزین می‌کند. [ابزار سلامت](../scripts/healthcheck.mjs) مقصد صریح
می‌خواهد؛ import آن مجوز یا اجرای درخواست شبکه نیست. آزمون‌ها پاسخ ساختگی یا
شنوندهٔ loopback متعلق به آزمون دارند و به API موجود متصل نمی‌شوند. فایل‌های نمونهٔ
عمومی فقط جای‌نگهدار سورس‌اند؛ محیط واقعی اپراتور، کلید و داده بیرون کد و artifact
می‌ماند.

مسیرهای `--template`، `--public-values-file` و `--output` در ابزار رندر باید داخل
مخزنی بمانند که مالک اسکریپت است. مسیر نسبی از ریشهٔ همان مخزن محاسبه می‌شود و به
پوشهٔ کاری فرمان وابسته نیست؛ مسیر محلی مطلق داخل آن نیز پذیرفته می‌شود. هر سه
مسیر پیش از خواندن قالب یا مقدار عمومی و ساخت خروجی بررسی می‌شوند. بخش پیمایش
مانند `..`، نام فایل با کدگذاری URL، مسیر وابسته به پوشهٔ جاری درایو، مسیر شبکه،
لینک و والد غیرپوشه رد می‌شوند. `--force` فقط اجازهٔ جایگزینی فایل عادی و معتبر
خروجی در همان ریشه را می‌دهد و دسترسی به فایل اپراتور یا مسیر سرویس نصب‌شده در
بیرون مخزن ایجاد نمی‌کند.

مرجع‌های [Docker](../deploy/docker/README.fa.md) و
[native](../deploy/native/README.fa.md) مرز پیشنهادی سرویس و درگاه را شرح می‌دهند و
راهنمای اجرای این snapshot نیستند. پیش از برنامه‌ریزی فعال‌سازی بعدی،
[عملیات](release-operations.fa.md)، [staging](staging.fa.md) و
[مدل تهدید](security/threat-model.fa.md) را بخوانید.

## پذیرش پیش از استقرار قابل اجرا

پذیرش استقرار باید از artifact واقعی برنامه و [پروفایل اعتبارسنجی](validation.fa.md) پانزده‌بررسی همان درخت دقیق، شامل ساخت واقعی تولید و بودجه، API مستقل نصب‌شده، مرورگر و CSP و مقایسهٔ تصویری فعلی استفاده کند. سورس، ابزار، پلتفرم، هش artifact و نتیجهٔ واقعی را ثبت کنید. آزمون حفظ‌شدهٔ ابزار محلی سازگاری موتور یا سرویس را ثابت نمی‌کند؛ انتشار بعدی اجراکننده و گردش کار عملیاتی باید وابستگی و پذیرش مستقل خود را کامل کند.

پیش از فعال‌سازی اپراتور، میزبان و forwarding مورداعتماد، کوکی هم‌مبدأ API، تنظیم
زمان درخواست، CSP و cache، دارایی و فونت، مقصد صریح سلامت، مالکیت گواهی و هویت
غیرقابل‌بازنویسی نسخه بررسی شود. بازگشت با artifact و تنظیم مطابق قبلی و cache
نوشتنی جدا برای هر نسخه تأیید شود. مجوز، ماندگاری، migration و بازیابی داده مسئولیت
مالک API مستقل می‌ماند. انتشار این ابزار و راهنما هیچ استقرار، بازگشت یا تغییر
زیرساختی انجام نمی‌دهد.
