# نسخه‌بندی و مالکیت artifact

[English](releasing.md) · [فارسی](releasing.fa.md)

مرحلهٔ **delivery-tooling** مقدار `applicationReady:false` را حفظ می‌کند.
[پیکربندی انتشار](../release-please-config.json)،
[manifest نسخه](../.release-please-manifest.json) و [changelog](../CHANGELOG.fa.md)
محلی، رکورد سورس‌اند. مدخل تاریخی فقط محدودهٔ ثبت‌شدهٔ خود را شرح می‌دهد و build،
انتشار یا استقرار این snapshot مستقل را ثابت نمی‌کند. عنوان Conventional Commit
ورودی نسخه‌بندی آینده است و خودکار tag منتشر یا PR انتشار ایجاد نمی‌کند.

[بسته‌بند artifact](../scripts/package-release.mjs) شناسهٔ صریح نسخه را اعتبارسنجی
و در ریشه با آمادگی صریح، از ورودی محلی شبیه build مقصد تازه و
انحصاری ایجاد می‌کند؛ آزمون مالک ریشهٔ ساختگی دارد. نگهبان عمومی آمادگی در سورس غیرقابل اجرای فعلی این عملیات
را رد می‌کند. فراداده، build
ارائه‌شده و پلتفرم اجرا را مشخص می‌کند.
[آزمون مالک](../scripts/package-release.test.mjs) رفتار فایل ساختگی، حذف رده‌های
ممنوع و حالت شکست را بررسی می‌کند؛ نه artifact قابل اجرای Linux، بازتولید میان
ماشین‌ها یا گراف کامل وابستگی نصب‌شده را. بستهٔ فعلی فرمان build، start یا انتشار
نسخه ندارد.

پیش از انتشار واقعی بعدی، برنامه تحویل و تأیید شود، تمام gateهای الزامی آن پاس
شوند، build با ابزار قفل‌شده روی پلتفرم مقصد انجام و هش سورس و artifact و سازگاری
ثبت شود. محتوای واقعی artifact بازبینی شود؛ حذف نام فایل به‌تنهایی رمز جاسازی‌شده
در فایل مجاز را شناسایی نمی‌کند. شناسهٔ غیرقابل‌بازنویسی، تنظیم اپراتور و مالکیت دادهٔ
API جدا بمانند. خروجی ناموفق شاهد قابل بررسی است و مجوز بازنویسی پوشهٔ نسخهٔ موجود
نیست.

پیش از commit، push یا تحویل PR مجاز، [gate مرجع فعلی](validation.fa.md) کامل اجرا
شود. انتشار، فعال‌سازی workflow ارائه‌دهنده و استقرار همچنان اقدام مجاز جدا هستند.
[عملیات](release-operations.fa.md) و [پذیرش استقرار](deployment.fa.md) را بخوانید؛
این راهنما هیچ‌کدام را فعال نمی‌کند.
