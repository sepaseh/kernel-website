# نسخه‌بندی و مالکیت artifact

[English](releasing.md) · [فارسی](releasing.fa.md)

مرحلهٔ operations سورس قابل اجرا و تعریف محافظت‌شدهٔ بسته‌بندی و گردش کار انتشار دارد؛ نشانگر true آن نسخه‌ای منتشر نمی‌کند. [پیکربندی انتشار](../release-please-config.json)، [manifest نسخه](../.release-please-manifest.json) و [changelog](../CHANGELOG.fa.md) محلی رکورد سورس‌اند. مدخل تاریخی فقط محدودهٔ ثبت‌شدهٔ خود را شرح می‌دهد و انتشار یا استقرار این snapshot مستقل را ثابت نمی‌کند. عنوان Conventional Commit ورودی نسخه‌بندی است؛ release-please تنها از گردش کار دستی و main-only با مجوز جدا اجرا می‌شود.

[بسته‌بند artifact](../scripts/package-release.mjs) شناسهٔ صریح نسخه را اعتبارسنجی و در ریشه با آمادگی صریح، از ورودی محلی شبیه ساخت مقصد تازه و انحصاری ایجاد می‌کند. آمادگی false یا نامعتبر پیش از عملیات رد می‌شود. فراداده، ساخت ارائه‌شده و پلتفرم اجرا را مشخص می‌کند. [آزمون مالک](../scripts/package-release.test.mjs) ریشهٔ مصنوعی برای رفتار فایل، حذف رده‌های ممنوع و شکست دارد؛ artifact قابل اجرای Linux، بازتولید میان ماشین‌ها یا گراف کامل وابستگی نصب‌شده را ثابت نمی‌کند. فرمان `npm run deploy:package -- --release=release-id` پس از ساخت واقعی آماده‌شده از واسط عملیاتی محافظت‌شده استفاده و تنها artifact محلی انحصاری ایجاد می‌کند. گردش کار دستی بسته‌بندی، فقط روی main، API نسخه‌ثابت را مستقل نصب می‌کند، با ورودی مصنوعی عمومی می‌سازد و همان artifact را بارگذاری می‌کند. گردش کار جداگانهٔ release-please تنها با مجوز صریح اقدام راه‌دور می‌تواند PR انتشار یا tag ایجاد کند.

ریشهٔ ورودی و والدهای مقصد باید پوشه‌های فیزیکی محلی باشند و هیچ والد پیوندی
نداشته باشند. ریشه‌ای را که آگاهانه انتخاب کرده‌اید، پیش از اعتبارسنجی به مسیر
واقعی آن تبدیل کنید؛ fixtureهای موقت آزمون مالک نیز همین کار را انجام می‌دهند.
در تمام مدت آماده‌سازی و بسته‌بندی، درخت‌های ورودی و خروجی باید فقط یک نویسنده
داشته باشند.

در کپی با بازنویسی، محتوا به‌صورت جریانی در فایل موقتی نوشته می‌شود که به‌صورت
انحصاری در پوشهٔ مقصد ساخته شده است. مجوزهای ورودی حفظ، هر دو دستگیرهٔ فایل بسته
و فایل موقت با rename جایگزین مقصد می‌شود. بنابراین پیوندی که در مؤلفهٔ نهایی
جایگزین شده باشد، بدون نوشتن در هدف آن تعویض می‌شود؛ عملیات ناموفق فقط فایل موقت
متعلق به خودش را حذف می‌کند. بررسی مسیر، دسترسی بدون دنبال‌کردن پیوند و مبتنی بر
دستگیره برای پوشه‌های والد فراهم نمی‌کند و درخت ورودیِ هم‌زمان تغییریافته را نیز
محافظت نمی‌کند. همچنان درخت مورد اعتماد و بدون نویسندهٔ هم‌زمان لازم است؛ این
آزمون‌ها حفاظت در برابر رقابت تغییر پوشه‌های والد را ثابت نمی‌کنند.

پیش از انتشار واقعی بعدی، برنامه تحویل و تأیید شود، تمام gateهای الزامی آن پاس
شوند، build با ابزار قفل‌شده روی پلتفرم مقصد انجام و هش سورس و artifact و سازگاری
ثبت شود. محتوای واقعی artifact بازبینی شود؛ حذف نام فایل به‌تنهایی رمز جاسازی‌شده
در فایل مجاز را شناسایی نمی‌کند. شناسهٔ غیرقابل‌بازنویسی، تنظیم اپراتور و مالکیت دادهٔ
API جدا بمانند. خروجی ناموفق شاهد قابل بررسی است و مجوز بازنویسی پوشهٔ نسخهٔ موجود
نیست.

پیش از commit، push یا تحویل PR مجاز، [gate مرجع فعلی](validation.fa.md) کامل اجرا
شود. انتشار، فعال‌سازی workflow ارائه‌دهنده و استقرار همچنان اقدام مجاز جدا هستند.
[عملیات](release-operations.fa.md) و [پذیرش استقرار](deployment.fa.md) را بخوانید؛
این راهنما هیچ‌کدام را فعال نمی‌کند.
