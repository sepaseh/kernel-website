# آماده‌سازی انتشار و محیط

[English](release-operations.md) · [فارسی](release-operations.fa.md)

مرحلهٔ operations [دروازهٔ برنامه](validation.fa.md) کامل پانزده‌بررسی را حفظ و سورس شش گردش کار عملیاتی را اضافه می‌کند. [CodeQL](../.github/workflows/codeql.yml) تحلیل خودکار JavaScript و TypeScript را برای push شاخهٔ main، PR با مقصد main و برنامهٔ هفتگی، به‌علاوهٔ اجرای دستی تعریف می‌کند. پنج گردش کار دیگر دستی و فقط روی main هستند: انتشار نسخه، بسته‌بندی، staging بیرونی، smoke استقرار و DAST. تعریف سورس و آزمون معنایی، دسترس‌پذیری سرویس، اسکن کامل‌شده، artifact بارگذاری‌شده یا استقرار را ثابت نمی‌کند. Sonar بومی و CodeRabbit همچنان تابع [حفاظت شاخه](branch-protection.fa.md) و [پیش‌بررسی head دقیق](sonarqube.fa.md) هستند.

[پیکربندی نسخه](releasing.fa.md) و مدخل تاریخی changelog، tag، artifact بارگذاری‌شده، اجرای سرویس بررسی یا سرویس مستقر را ثابت نمی‌کند. [بسته‌بند](../scripts/package-release.mjs) artifact محلی صریح می‌گیرد و آزمون مالک مصنوعی را حفظ می‌کند؛ ساخت برنامه را فراخوانی و نسخهٔ انتشار ایجاد نمی‌کند. برای پذیرش برنامه از نتیجهٔ ساخت واقعی استفاده کنید. آماده‌سازی محلی مجوز commit، push، اجرای گردش کار، فراهم‌کردن secret یا فعال‌سازی زیرساخت نیست.

[واسط عملیاتی](../scripts/operations-checks.mjs) از `deploy:package`، `test:smoke` و `test:staging` محافظت می‌کند. بسته‌بندی ساخت محلی آماده و شناسهٔ انحصاری نسخه را مصرف می‌کند؛ حالت مرورگر پیش از یافتن SDK دقیق نصب‌شده، مقصد عمومی صریح را اعتبارسنجی و محیط والد با فهرست مجاز منتقل می‌کند. smoke در Docker و Lighthouse اجراکنندهٔ مستقل تحت مالکیت دارند. این چهار عملیات دستی و فرمان آزمایشگاهی توصیه‌ای بیرون `full` می‌مانند.

[اعتبارسنج‌های مقصد](../scripts/validate-workflow-targets.mjs) ورودی صریح
staging، smoke و DAST را بدون تماس با URL می‌سنجند. staging میزبان تنظیم‌شدهٔ دقیق
برنامه و API را مقایسه می‌کند. smoke افزون بر آن شناسهٔ صریح استقرار را با شناسهٔ
موردانتظار تطبیق می‌دهد. DAST میزبان مجاز و میزبان production جداگانه را مقایسه
می‌کند. این کنترل واژگانی است، نه تثبیت DNS، بررسی redirect یا اثبات غیرproduction
بودن میزبان؛ alias یا allowlist نادرست همچنان بازبینی اپراتور می‌خواهد. این توابع
هیچ scanner یا اجراکنندهٔ مرورگر ندارند.

[ابزار پاک‌سازی](../scripts/docker-smoke-cleanup.mjs) عملیات Docker و Compose تزریقی
را می‌پذیرد و نام منبع تولیدشده و فایل موقت متعلق به اجرا را محدود می‌کند.
[آزمون آن](../scripts/docker-smoke-cleanup.test.mjs) callback ساختگی و فایل موقت
دارد؛ سازگاری engine یا حذف موفق منبع واقعی را ثابت نمی‌کند. خطای پاک‌سازی شکست
می‌ماند و image، cache و استقرار نامرتبط هرگز نباید سراسری prune شوند.

عملیات اجرای واقعی به gate برنامهٔ جداگانهٔ بازبینی‌شده، منشأ معتبر fixture، هویت
دقیق artifact و مقصد، حداقل دسترسی ارائه‌دهنده و مجوز صریح نیاز دارد. fork و سورس
نامطمئن نباید اعتبارنامهٔ fixture خصوصی بگیرد. اجرای واقعی، شکست و منبع باقی‌مانده
ثبت شود؛ نبود شاهد یکپارچگی به موفقیتِ ردشده تبدیل نشود.
[پذیرش staging](staging.fa.md)، [پذیرش استقرار](deployment.fa.md) و
[بازبینی امنیت](security/reviews.fa.md) را دنبال کنید.
