# نمونهٔ مستقل API مصنوعی

[English](api-fixture.md) · [فارسی](api-fixture.fa.md)

پیش‌نیاز تاریخی و ۳۴۸فایلی api-fixture، مبدل مستقل نسخه‌ثابت را با حفظ `applicationReady:false` و ۶۶ ماژول محصول معرفی کرد. [مرحلهٔ فعلی برنامه](application.fa.md) این مبدل را در سورس قابل اجرا یکپارچه می‌کند، محافظ‌های آن را حفظ و هر پانزده بررسی مرجع را ثبت می‌کند. دروازهٔ کامل و ایزولهٔ همان سورس دقیق، اجرای واقعی API و مرورگر و هویت ثبت‌شدهٔ سورس معیار پذیرش‌اند؛ آستانهٔ واحد و راهبری ۹۰٪ و ۸۰٪ باقی می‌ماند.

## قرارداد مبدل منتشرشده

بررسی Git به نصب عادی و بدون پیوند سیستم در C:/Program Files/Git/cmd/git.exe در Windows یا /usr/bin/git در Unix نیاز دارد. فرزند Git فقط مسیرهای ثابت سیستم و ریشهٔ استاندارد Windows را دریافت می‌کند و مسیر جست‌وجوی ارائه‌شده توسط فراخواننده را مصرف نمی‌کند. نبود نصب یا نصب در محل دیگر با خطا متوقف می‌شود؛ کشف فایل اجرایی یا override اپراتور وجود ندارد. ساخت محیط فرایند Node و API قرارداد جداگانه است.

اجراکنندهٔ API متعلق به وب‌سایت اکنون مخزن عمومی sepaseh/kernel-api را در نسخهٔ تغییرناپذیر 4755d62d14fb9d53cbe9d6246ca9be6bb4a3a7a9 مصرف می‌کند. عملیات قابل اجرای مصنوعیِ مجاز به KERNEL_API_DIRECTORY صریح و مطلق، متصل به دریافت تازه و جداگانه‌نصب‌شده، نیاز دارد. مخزن همسایه کشف یا وارد منبع نمی‌شود. پس از تأیید آمادگی، حل‌کننده پوشهٔ عادی و مستقل Git، ریشه و HEAD مورد انتظار، پاک‌بودن منبع ردیابی‌شده و تطابق manifest، lock و هویت وابستگی مستقیم نصب‌شده را بررسی و سپس src/index.ts منتشرشدهٔ API را انتخاب می‌کند. این کنترل، گواهی تمام بایت‌های بستهٔ نصب‌شده نیست.

اجراکننده از ورودی مصنوعی صریح loopback، NODE_ENV=test، راز احراز هویت تولیدشده فقط برای نمونه، OTP عمومی ثابت آزمایشی، دادهٔ اولیه و SQLite و ذخیره‌سازی اشیای تازه و متعلق به آزمون خارج از منبع استفاده می‌کند. پیش از پاک‌سازی وضعیت، فرزند متعلق به خود را کاملاً متوقف می‌کند و خطای عملیات و پاک‌سازی را حفظ می‌کند. نشانگر false همچنان عملیات را پیش از تنظیمات، Git، SDK یا فرایند رد می‌کند. آزمون مالک Node از پروژهٔ موقت نشان‌دار، برنامهٔ API و SDK مصنوعی و مرز Git صریحاً mock‌شده استفاده می‌کند؛ این آزمون، اجرای واقعی API یا مرورگر نیست.

اجراکنندهٔ API در Playwright تنظیمات والد با مبدأ وب‌سایت را دریافت می‌کند؛ فقط اجراکنندهٔ API پورت فرزند API را استخراج می‌کند. اعتبارسنجی سخت‌گیرانهٔ محیط SDK، نشانگر واقعی worker یعنی PLAYWRIGHT_TEST را فقط به‌صورت ویژگی داده با مقدار ثابت 1 و هویت بازبینی‌شدهٔ Playwright نصب‌شدهٔ 1.64.1 می‌پذیرد. کلید خصوصی، loader یا تزریق کد دلخواه همچنان رد می‌شود. تشخیص کلید نامنتظر فقط نام escape‌شده و محدود را ثبت می‌کند و مقدار را نمی‌خواند یا نمایش نمی‌دهد.

## دامنه و پذیرش بعدی

ترکیب فعلی برنامه این قراردادهای مبدل و اجراکننده را همراه مسیر، چیدمان و CSS واقعی، هر پانزده بررسی مرجع، fixture مستقل نصب‌شدهٔ API و مرورگر و پذیرش ساخت و بودجه، مرورگر و CSP و تصویر Windows روی درخت دقیق حفظ می‌کند. پیش از ادغام قابل اجرا موفقیت واقعی build/e2e/visual را مشاهده و بررسی‌هایشان را صریح الزامی کنید. نشانگر سورس، callback تزریقی و PNG تاریخی جای این شواهد را نمی‌گیرد.

نتیجهٔ بستهٔ توسعهٔ قبلی، درخت انتشار متفاوت را اعتبارسنجی نمی‌کند. پیش از هر commit، push یا تحویل مجاز، نصب تازهٔ Node و Python نسخه‌ثابت و مجموعهٔ کامل پانزده‌بررسی روی سورس دقیق و ایزولهٔ برنامهٔ پیشنهادی لازم است. فایل اولیه، بایگانی بازیابی، تاریخ مبنای تصویری و تمام وضعیت خصوصی حفظ شوند. استقرار و عملیات محیط واقعی مجوز جداگانه می‌خواهند.
