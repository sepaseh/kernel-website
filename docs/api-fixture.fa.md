# نمونهٔ مستقل API مصنوعی

[English](api-fixture.md) · [فارسی](api-fixture.fa.md)

مرحلهٔ api-fixture نشانگر applicationReady:false و شصت‌وشش ماژول محصول بازبینی‌شده را حفظ می‌کند. فهرست دقیق ۳۴۸فایلی، پایهٔ مرورگر را با این جفت راهنما و پشتیبان مشترک آزمون Node تکمیل می‌کند. این نسخهٔ منتشرشده مسیر قابل اجرا، چیدمان ریشه یا زنجیرهٔ CSS ندارد. هر یازده بررسی مرجع الزامی و آستانهٔ پوشش واحد و راهبری به‌ترتیب ۹۰٪ و ۸۰٪ باقی می‌مانند.

## قرارداد مبدل منتشرشده

بررسی Git به نصب عادی و بدون پیوند سیستم در C:/Program Files/Git/cmd/git.exe در Windows یا /usr/bin/git در Unix نیاز دارد. فرزند Git فقط مسیرهای ثابت سیستم و ریشهٔ استاندارد Windows را دریافت می‌کند و مسیر جست‌وجوی ارائه‌شده توسط فراخواننده را مصرف نمی‌کند. نبود نصب یا نصب در محل دیگر با خطا متوقف می‌شود؛ کشف فایل اجرایی یا override اپراتور وجود ندارد. ساخت محیط فرایند Node و API قرارداد جداگانه است.

اجراکنندهٔ API متعلق به وب‌سایت اکنون مخزن عمومی sepaseh/kernel-api را در نسخهٔ تغییرناپذیر 4755d62d14fb9d53cbe9d6246ca9be6bb4a3a7a9 مصرف می‌کند. عملیات قابل اجرای مجاز در آینده به KERNEL_API_DIRECTORY صریح و مطلق، متصل به دریافت تازه و جداگانه‌نصب‌شده، نیاز دارد. مخزن همسایه کشف یا وارد منبع نمی‌شود. پس از تأیید آمادگی، حل‌کننده پوشهٔ عادی و مستقل Git، ریشه و HEAD مورد انتظار، پاک‌بودن منبع ردیابی‌شده و تطابق manifest، lock و هویت وابستگی مستقیم نصب‌شده را بررسی و سپس src/index.ts منتشرشدهٔ API را انتخاب می‌کند. این کنترل، گواهی تمام بایت‌های بستهٔ نصب‌شده نیست.

اجراکننده از ورودی مصنوعی صریح loopback، NODE_ENV=test، راز احراز هویت تولیدشده فقط برای نمونه، OTP عمومی ثابت آزمایشی، دادهٔ اولیه و SQLite و ذخیره‌سازی اشیای تازه و متعلق به آزمون خارج از منبع استفاده می‌کند. پیش از پاک‌سازی وضعیت، فرزند متعلق به خود را کاملاً متوقف می‌کند و خطای عملیات و پاک‌سازی را حفظ می‌کند. نشانگر false فعلی عملیات واقعی را پیش از تنظیمات، Git، SDK یا فرایند رد می‌کند. آزمون مالک Node از پروژهٔ موقت نشان‌دار، برنامهٔ API و SDK مصنوعی و مرز Git صریحاً mock‌شده استفاده می‌کند؛ این آزمون، اجرای واقعی API یا مرورگر نیست.

اجراکنندهٔ API در Playwright تنظیمات والد با مبدأ وب‌سایت را دریافت می‌کند؛ فقط اجراکنندهٔ API پورت فرزند API را استخراج می‌کند. اعتبارسنجی سخت‌گیرانهٔ محیط SDK، نشانگر واقعی worker یعنی PLAYWRIGHT_TEST را فقط به‌صورت ویژگی داده با مقدار ثابت 1 و هویت بازبینی‌شدهٔ Playwright نصب‌شدهٔ 1.64.1 می‌پذیرد. کلید خصوصی، loader یا تزریق کد دلخواه همچنان رد می‌شود. تشخیص کلید نامنتظر فقط نام escape‌شده و محدود را ثبت می‌کند و مقدار را نمی‌خواند یا نمایش نمی‌دهد.

## دامنه و پذیرش بعدی

این پیش‌نیاز، مبدل API و اصلاح اجراکننده را از انتشار بزرگ‌تر برنامه جدا می‌کند تا هر PR حداکثر ۱۰۰ ورودی تغییر دهد. یکپارچه‌سازی بعدی باید main واقعاً ادغام‌شده را تطبیق دهد، مسیر و چیدمان و CSS واقعی منتشر کند، پروفایل مرجع را به پانزده بررسی گسترش دهد، API و مرورگر نسخه‌ثابت را جداگانه نصب و ساخت و بودجه، مرورگر و CSP و مقایسهٔ تصویری Windows را روی درخت دقیق پیشنهادی واقعاً اجرا کند. پیش از ادغام برنامهٔ قابل اجرا، موفقیت واقعی build/e2e/visual مشاهده و الزامی‌شدنشان صریحاً تأیید شود. نشانگر منبع، callback تزریقی و PNG تاریخی جایگزین این شاهد نیستند.

نسخهٔ بزرگ‌تر محلی و منتشرنشده می‌تواند تشخیص توسعه‌ای مفید بدهد؛ نتیجهٔ آن اعتبارسنجی این نسخهٔ منتشرشدهٔ متفاوت محسوب نمی‌شود. پیش از هر commit، push یا تحویل مجاز، نصب تازهٔ Node و Python نسخه‌ثابت و مجموعهٔ کامل یازده‌بررسی روی منبع جداشدهٔ دقیق لازم است. فایل اولیه، بایگانی بازیابی، تاریخ مبنای تصویری و تمام وضعیت خصوصی حفظ شوند. استقرار و عملیات محیط واقعی مجوز جداگانه می‌خواهند.
