# پایهٔ اجراکننده‌های Node

[English](runner-foundation.md) · [فارسی](runner-foundation.fa.md)

## مرحلهٔ سورس و فعال‌سازی

این مالکان فرایند در مرحلهٔ ۳۱۷فایلی `runner-foundation` معرفی شدند.
[نشانگر سورس](../.github/bootstrap-policy.json) مالک فهرست دقیق و آمادگی نسخهٔ
فعلی است؛ افزودن مستندات زمان اجرا را فعال نمی‌کند. نسخهٔ فعلی
`application-guidance` مقدار `applicationReady:false` و پروفایل یازده‌بررسی پایه
را حفظ می‌کند. عملیات ورودی وب‌سایت، API، سرور و تحلیلگر این نشانگر را پیش از
خواندن محیط و پیکربندی، تعیین وابستگی، دسترسی به خروجی یا ساخت فرزند رد می‌کنند.
برای اجرای نسخهٔ ناقص آن را تغییر ندهید. [پذیرش برنامه](application.fa.md)
سورس مستقل موردنیاز، دروازهٔ پانزده‌بررسی و گذار ادغام محافظت‌شده را تعریف می‌کند.

[نمونهٔ مستقل API](api-fixture.fa.md) مبدل عمومی نسخه‌ثابت، وضعیت تازهٔ تحت مالکیت،
قرارداد پورت اجراکننده و کنترل سخت‌گیرانهٔ worker در SDK را تعریف می‌کند. import
عادی بی‌اثر می‌ماند: dotenv خوانده نمی‌شود، محیط تغییر نمی‌کند، سرویس آغاز نمی‌شود
و CLI نصب‌شده جست‌وجو نمی‌شود. آزمون‌های مالک Node در پایین قرارداد فرایند را
مستقل از اجرای بعدی برنامه، API یا مرورگر می‌سنجند.

## مالکان و قراردادها

| مالک                                                                          | رفتار                                                                                                                                                                                                                      |
| ----------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [runner-process.mjs](../scripts/runner-process.mjs)                           | یک فرزند مستقیم متعلق به خود را با دستور، آرگومان، پوشهٔ کاری و محیط صریح آغاز می‌کند؛ خطای ساخت، خروج، سیگنال و لغو را گزارش می‌دهد و رویداد close را تا پایان دنبال می‌کند. شنونده‌های سیگنال CLI محدودند و حذف می‌شوند. |
| [runner-inputs.mjs](../scripts/runner-inputs.mjs)                             | ابتدا آمادگی را بررسی می‌کند، وجود dotenv را بدون خواندن محتوا رد می‌کند، محیط عمومی صریح می‌سازد و هویت Next محلی یا اسکریپت API مصنوعی انتخاب‌شده را اعتبارسنجی می‌کند.                                                  |
| [start-website.mjs](../scripts/start-website.mjs)                             | تنظیم صریح وب‌سایت را می‌سنجد، فایل‌های مستقل محافظت‌شده را آماده می‌کند و منتظر سرور Node متعلق به خود می‌ماند.                                                                                                           |
| [test-website-api.mjs](../scripts/test-website-api.mjs)                       | تنظیم صریح loopback مصنوعی و محل مطلق fixture API را می‌خواهد، نقطهٔ ورود ثابت آن را می‌سنجد و منتظر fixture Node متعلق به خود می‌ماند.                                                                                    |
| [test-website-server.mjs](../scripts/test-website-server.mjs)                 | ساخت Next تأییدشدهٔ ریشهٔ انتخاب‌شده را اجرا و فایل مستقل را آماده می‌کند؛ فقط پس از موفقیت سرور را آغاز می‌کند. حالت صریح صرف‌نظر از ساخت، شناسهٔ ساخت موجود و محافظت‌شده می‌خواهد.                                       |
| [analyze-website-performance.mjs](../scripts/analyze-website-performance.mjs) | دستور تحلیل Next محلی تأییدشده را اجرا می‌کند و خروجی محدود را در فایل متعلق به خود که انحصاری ساخته شده می‌نویسد؛ خطا فایل موجود نامرتبط را حفظ می‌کند.                                                                   |

هیچ عملیات عمومی، پوشهٔ کاری دیگری را ضمنی پیدا نمی‌کند. تعیین Next از نام و
نسخهٔ دقیق manifest، قفل و `node_modules/next` نصب‌شدهٔ همان ریشه، با مسیر بدون
پیوند، استفاده می‌کند؛ CLI والد یا سراسری جایگزین نمی‌شود. تعیین‌کنندهٔ API به KERNEL_SYNTHETIC_ENV=1 و KERNEL_API_DIRECTORY مطلق و صریح نیاز دارد. دریافت مستقل و پاک Git در نسخهٔ عمومی 4755d62d14fb9d53cbe9d6246ca9be6bb4a3a7a9 و تطابق manifest، lock و هویت وابستگی مستقیم نصب‌شده را بررسی و سپس src/index.ts منتشرشده را انتخاب می‌کند. این کنترل، گواهی تمام بایت نصب‌شده یا سازگاری قرارداد ارتباطی نیست؛ یکپارچگی واقعی همچنان به بررسی مرحلهٔ بعدی برنامه نیاز دارد.

ورودی محیط صریح است. تنظیم وب‌سایت شامل `NODE_ENV` تولید، `API_BASE_URL`،
`HOSTNAME` و `PORT` و تنظیم عمومی آدرس، ایندکس و CSP است. فقط متغیرهای ضروری
زمان اجرا در فهرست مجاز و تنظیم عمومی اعلام‌شده به فرزند می‌رسند؛ اطلاعات ورود،
`NODE_OPTIONS` و بقیهٔ محیط والد حذف می‌شوند. اجرای مصنوعی همچنین دو مبدأ متفاوت
`http://127.0.0.1:PORT`، میزبان و پورت هماهنگ وب‌سایت و غیرفعال‌بودن صریح ایندکس
را می‌خواهد. آدرس پیش‌فرض API یا جایگزین dotenv وجود ندارد.

ابزار عمومی فرایند پس از بررسی آمادگی توسط عملیات ورودی فراخوانی می‌شود؛ ریشهٔ سورس ندارد و آن سیاست را دوباره بررسی نمی‌کند. این ابزار شیء فرزند مستقیمی را که خودش ساخته مالک است. لغو و توقف تکرارپذیر
از پایان‌دادن محدود، تشدید توقف و انتظار برای close روی همان شیء استفاده می‌کند؛
جست‌وجوی PID سراسری، کشتن درخت فرایند یا پاک‌سازی فرایند دیگر ندارد. این قرارداد
نوادگان فرزند را نظارت نمی‌کند. اپراتور برای زمان اجرای آینده‌ای که نظارت بر
نوادگان می‌خواهد، باید محدودسازی مستقل فراهم کند. بررسی فایل‌سیستم یک نویسنده و
ریشهٔ فیزیکی بدون پیوند را فرض می‌کند؛ عملیات قابل‌انتقال مسیر، رقابت را حذف نمی‌کند.

## بررسی واقعی

شش فایل آزمون مالک Node عبارت‌اند از
[چرخهٔ عمر فرایند](../scripts/runner-process.test.mjs)،
[ورودی‌ها](../scripts/runner-inputs.test.mjs)،
[آغاز مستقل](../scripts/start-website.test.mjs)،
[آغاز API](../scripts/test-website-api.test.mjs)،
[ترتیب ساخت و سرور](../scripts/test-website-server.test.mjs) و
[خروجی تحلیل](../scripts/analyze-website-performance.test.mjs).
موارد مثبت برنامه‌های موقت Node را در پروژه‌های مصنوعی متعلق به خود با نشانگر
صریح آماده اجرا می‌کنند. اجرای واقعی فرزند و خطاهای آن بررسی می‌شود، نه فقط callback
ساختگی. موارد منفی نشانگر false را نگه می‌دارند و بی‌اثرماندن ورودی و عملیات را
ثابت می‌کنند. فایل و فرایند هر آزمون متعلق به همان آزمون است؛ dotenv واقعی، API
توسعه‌دهنده، وضعیت اپراتور و محیط عملیاتی fixture نیستند.

[فهرست مرجع](../.agents/validation.json) مالک پروفایل کامل است که فعلاً هر یازده
بررسی را حفظ می‌کند.
این مالکان از مسیرهای سورس موجود و بدون استثنا یا حد ضعیف‌تر، به پوشش واقعی
گردش‌کار و Sonar می‌پیوندند. برای بررسی محدود توسعه می‌توان اجرا کرد:

```sh
node --test scripts/runner-process.test.mjs scripts/runner-inputs.test.mjs scripts/start-website.test.mjs scripts/test-website-api.test.mjs scripts/test-website-server.test.mjs scripts/analyze-website-performance.test.mjs
```

commit، push یا تحویل PR مجاز همچنان نصب تازهٔ Node و وابستگی پین‌شدهٔ Python و
`npm run validate -- full` را روی درخت دقیق جداگانه می‌خواهد. فهرست ۶۶ماژولی محصول،
مالکیت آزمون سورس، محافظ زمان فعال‌سازی توکن عملیات و بررسی فونت در این نسخهٔ
نشانگر false حفظ می‌شوند؛ [مالکیت نشست](session.fa.md) را بخوانید.

قبولی این آزمون‌های مالک Node، ساخت یا اجرای واقعی Next.js، سازگاری API مستقل،
مرورگر و CSP، دسترس‌پذیری، مقایسهٔ تصویر، Lighthouse، Docker یا استقرار را ثابت
نمی‌کند. [پایهٔ مرورگر](browser-foundation.fa.md) سناریوهای نوشته‌شده با SDK و
اجرای کنترل‌شده را مستند می‌کند. هر نسخهٔ قابل اجرا باید قرارداد برنامه را
برآورده کند و نتیجهٔ تازهٔ همان درخت دقیق را ارائه دهد؛ پیش از ادغامش، موفقیت
واقعی jobهای build، e2e و visual را مشاهده و الزامی کنید. [آزمون](testing.fa.md)،
[اعتبارسنجی](validation.fa.md)، [سیاست مرحله](bootstrap.fa.md) و
[پذیرش تحویل](deployment.fa.md) را بخوانید.
