# قرارداد مقصد و اجرای staging

[English](staging.md) · [فارسی](staging.fa.md)

[اعتبارسنج خالص مقصد](../scripts/validate-workflow-targets.mjs) و [آزمون Node آن](../scripts/validate-workflow-targets.test.mjs) ورودی صریح را بدون بازکردن URL، resolve کردن DNS، دنبال‌کردن redirect یا اجرای مرورگر و scanner بررسی می‌کنند. [واسط عملیاتی](../scripts/operations-checks.mjs) اکنون فرمان ثبت‌شدهٔ `test:smoke` و `test:staging` را فراهم می‌کند و فقط ورودی عمومی اعتبارسنجی‌شده را به SDK دقیق نصب‌شدهٔ Playwright می‌دهد. سورس گردش کار دستی و main-only برای staging، smoke استقرار و DAST وجود دارد؛ اجرای واقعی بیرونی از دروازهٔ الزامی برنامه جدا می‌ماند.

گردش کار دستی پیش از اعتبارسنجی خالص مقصد، Node نسخه‌ثابت را نصب و مرورگر را با CLI نصب‌شدهٔ ریشه پیدا می‌کند، نه دریافت نسخهٔ آزاد از `npx`. فرمان `test:smoke` از Chromium و `test:staging` از Chromium و Firefox و WebKit استفاده می‌کند. پیکربندی SDK مقدار محیطی فیلترنشده را رد می‌کند و واسط فقط کلید عمومی معتبر مقصد و زمان اجرا را می‌دهد. DAST پیش از اقدام scanner نسخه‌ثابت، نام میزبان مجاز و ممنوع را می‌سنجد. هیچ‌یک از این تعریف‌های گردش کار، موفقیت مشاهده‌شدهٔ راه‌دور نیست.

staging به URL صریح برنامه و API و نام دقیق میزبان مجاز تنظیم‌شدهٔ آن‌ها نیاز دارد.
smoke ورودی نام‌گذاری‌شدهٔ جدا دارد و افزون بر آن شناسهٔ غیرخالی استقرار و شناسهٔ
موردانتظار برابر می‌خواهد. DAST مقصد صریح، میزبان مجاز و میزبان production جدا برای
ردکردن می‌خواهد. parser، اعتبارنامه، scheme غیرHTTP(S) و ورودی خراب یا دارای نویسهٔ
کنترلی را رد می‌کند. این قرارداد، allowlist را معتبر نمی‌کند و مانع alias مربوط به
production، تغییر DNS یا redirect بعدی نمی‌شود. پیش از هر درخواست، بازبینی اپراتور
و کنترل زمان اجرا باید این موارد را پوشش دهد.

بررسی واقعی بیرونی به مقصد واقعاً غیرproduction با مجوز جدا، artifact مستقر مشخص، سیاست
دادهٔ ساختگی و fixture سازگار مرورگر و API با نصب مستقل نیاز دارد. مسیر عمومی،
دارایی و فونت، noindex، حالت CSP، پاسخ سلامت و در صورت پیاده‌سازی marker نسخه در
عمل بررسی شود. build دقیق، مرورگر و پلتفرم، مقصد و شکست واقعی ثبت شود. مقصد از نظر
نحوی معتبر یا شناسهٔ ورودی برابر، هویت سرویس راه‌دور را ثابت نمی‌کند. noindex در
staging سیاست نمایه‌سازی است و کنترل دسترسی نیست.

[دروازهٔ برنامه](validation.fa.md) پانزده‌بررسی، شاهد ساخت محلی تحت مالکیت، API مستقل، مرورگر و CSP و تصویر را می‌خواهد. این شاهد استقرار staging بیرونی یا نتیجهٔ DAST نیست. آزمون مالک اعتبارسنج مقصد ورودی مصنوعی و محلی را حفظ می‌کند و هویت سرویس راه‌دور را ثابت نمی‌کند. دسترسی و اسکن مقصد بیرونی مجوز جدا می‌خواهد و import یا آزمون این توابع چنین مجوزی نمی‌دهد. [عملیات](release-operations.fa.md) و [بازبینی امنیت](security/reviews.fa.md) را بخوانید.
