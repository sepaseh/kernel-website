# ناوبری وظایف وب‌سایت

[English](source-navigation.md) · [فارسی](source-navigation.fa.md)

از [دستور ریشه](../AGENTS.md)، [تنظیم](../.agents/settings.json)، [نشانگر منبع](../.github/bootstrap-policy.json) و وظیفهٔ مرتبط در [ناوبری ماشینی](../.agents/navigation.json) آغاز کنید. نگاشت، صاحب و قرارداد و آزمون منتشرشده و شناسهٔ واقعی بررسی را تعیین می‌کند. مسیر، layout یا CSS پیشنهادی و سرویس اجرا‌نشده را تحویل‌شده فهرست نکنید. [مرحله](bootstrap.fa.md)، [معماری](architecture.fa.md) و [پذیرش برنامه](application.fa.md) منبع فعلی را از ترکیب آینده جدا می‌کنند.

- فرم و نشست: صاحب قابلیت، HTTP و نوع، [فرم](forms.fa.md) و [نشست](session.fa.md)، لغو، نسل، تعویض mount و حساب، مقصد OTP و راهبری دیررس را دنبال کنید.
- قرارداد HTTP: نوع قابلیت، قرارداد تنظیم و ماژول مشترک را ببینید؛ احراز هویت و ذخیره‌سازی واقعی API متعلق به سرویس مستقل است.
- زبان و پیام: تنظیم API، کاتالوگ همنام هر زبان، نوع کلید محوشوندهٔ مشتق از انگلیسی، بارگذار صریح و انتخاب root/auth/account را بررسی کنید. جهت را از کد زبان نسازید.
- طراحی: با [DESIGN](../DESIGN.fa.md)، [مهارت طراحی](../.agents/skills/design-ui/SKILL.md) و اجزای واقعی شروع کنید. کلاس معنایی به‌تنهایی CSS محاسبه‌شده، کنتراست یا تصویر نیست.
- HTTP، CSP، SEO، فونت و کارایی: صاحب و آزمون مستقیم را باز کنید. ترکیب چارچوب و اجرا را با نشانگر و موجودی و شاهد فعلی تأیید کنید.
- ابزار و راه‌انداز و مرورگر: [آزمون](testing.fa.md)، [راه‌انداز](runner-foundation.fa.md)، [مرورگر](browser-foundation.fa.md) و [fixture API](api-fixture.fa.md) را بخوانید. محافظ، هویت صریح fixture، ورودی و درگاه، فرزند متعلق به خود و پاک‌سازی را دنبال کنید. مسیر نوع‌سنجی‌شده، callback و تصویر اجرای مسیر نیست.
- تحویل و عملیات: [تحویل](deployment.fa.md)، [عملیات](release-operations.fa.md)، [واسط عملیاتی](../scripts/operations-checks.mjs)، [smoke در Docker](../deploy/docker/smoke.mjs)، [Lighthouse](../scripts/run-website-performance.mjs) و آزمون مالک آن‌ها را بررسی کنید. آمادگی، مقصد صریح، هویت ثابت API و مرورگر، مالکیت منبع و پاک‌سازی را دنبال کنید. فرمان دستی و توصیه‌ای بیرون full بماند؛ انتشار سورس مجوز اجرای راه‌دور نیست.
- Git: [سیاست Git](../.agents/rules/git.md)، [شاخه](../.agents/rules/branches.md) و مهارت مرتبط را بخوانید. کار و مجوز را حفظ، مبنای واقعی را تأیید و پس از ادغام واقعی پیش از انتشار بعدی تطبیق دهید.

تابع کامل صاحب را بخوانید و به تطابق خط اکتفا نکنید. بررسی را از [فهرست مرجع](../.agents/validation.json) و [مشارکت](../CONTRIBUTING.fa.md) انتخاب کنید. منبع دقیق، فرمان واقعی، شکست و مورد ردشده و محدودیت ثبت شود؛ گزارش سبز قدیمی شاهد تازه نیست. [ارزیابی](comprehension-evaluation.fa.md) فهم و کشف مشاهده‌شدهٔ دستور را جداگانه می‌سنجد. فهرست به‌تنهایی کامل بودن معنا یا بارگذاری خودکار را ثابت نمی‌کند.
