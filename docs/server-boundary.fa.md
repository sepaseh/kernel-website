# ابزارهای مرز سرور

[English](server-boundary.md) · [فارسی](server-boundary.fa.md)

این مرحله ابزارهای مستقل از فریم‌ورک برای ارسال درخواست به API و ساخت سیاست CSP
سند را همراه تست مصنوعی Node منتشر می‌کند. [مرحلهٔ پایهٔ رابط کلاینت](client-ui.fa.md) در مجموع پنجاه ماژول اجرایی و بیست‌وچهار فایل تست سورس دارد؛ این ابزارهای HTTP/CSP مستقل از فریم‌ورک باقی‌اند. مقدار `applicationReady:false` الزامی باقی می‌ماند.
این ابزارها مسیر Next.js، تولیدکنندهٔ nonce درخواست، نمایشگر یا رفتار مرورگر را
ارائه یا تأیید نمی‌کنند.

## ارسال درخواست به API

فایل `src/shared/api/proxy.ts` یک Web Request و بخش‌های صریح مسیر می‌گیرد. فقط
مسیرها و متدهای فهرست‌شدهٔ احراز هویت و حساب وب‌سایت به API مستقل می‌رسند. تغییرات
به Origin دقیقاً مطابق پروتکل درخواست و Host مرورگر نیاز دارند؛ هدرهای forwarded-host
مجوز درخواست نیستند. استقرار آینده باید Host و پروتکل مقصد معتبر را در این مرز
حفظ و میزبان‌های عمومی ناشناخته را رد کند. اعتبارسنجی نشانی API در `origin.ts`
محلی باقی می‌ماند.

درخواست فقط Cookie، Content-Type، Origin و X-Request-Id را با Accept از نوع JSON،
fetch بدون cache، تغییر مسیر دستی، لغو فراخواننده و مهلت پانزده‌ثانیه‌ای ارتباط با
API ارسال می‌کند. Authorization و ترجیح زبان مرورگر ارسال نمی‌شوند؛ زبان و جهت فعال
ذخیره‌شده متعلق به API است. تغییرات، نوع رسانهٔ application/json را با پارامترهای
اختیاری می‌پذیرند. بدنهٔ جریانی حداکثر ۳۲ کیبی‌بایت است؛ جریان بزرگ‌تر لغو می‌شود و
هر reader گرفته‌شده آزاد می‌شود. خطای خواندن یا لغو جریان، ارتباط یا JSON نامعتبر
احراز هویت، پاسخ عمومی 503 بدون جزئیات خصوصی می‌دهد.

تمام پاسخ‌ها، شامل رد محلی و خطای API، سیاست cache از نوع private و no-store دارند.
فقط Content-Type، X-Request-Id، Retry-After و تمام Set-Cookieها به مرورگر برمی‌گردند.
مقصد تغییر مسیر و هدر دلخواه API منتقل نمی‌شوند. JSON موفق احراز هویت، فیلدهای
شناخته‌شدهٔ اعتبارنامهٔ bearer و refresh را در اشیا و آرایه‌ها بازگشتی حذف می‌کند؛
کوکی‌های HttpOnly حفظ می‌شوند. پاسخ بدون بدنهٔ 204 یا 205، وضعیت و کوکی‌ها را حفظ
می‌کند. احراز هویت، مجوزدهی، ویژگی کوکی، اعتبارسنجی کسب‌وکار و ذخیره‌سازی همچنان
متعلق به API هستند.

## سیاست CSP

فایل `src/shared/security/csp.ts` تنظیم report-only یا enforce، الفبا و طول دقیق
nonce را بررسی می‌کند، سیاست محدود سند می‌سازد و مسیر سند را از API و دارایی‌های
ثابت و متادیتا تشخیص می‌دهد. اسکریپت و عنصر style در production از nonce ورودی
استفاده می‌کنند؛ ویژگی style موجود در SSR عمداً مجاز است. فقط حالت توسعه unsafe-eval
و WebSocket را مجاز می‌کند. این‌ها ابزار خالص هستند: تصادف تولید نمی‌کنند، nonce
مرورگر را معتبر نمی‌دانند، هدر نصب نمی‌کنند و اجرای CSP در مرورگر را ثابت نمی‌کنند.

## اعتبارسنجی و انتشارهای باقی‌مانده

پیش از commit، push یا تحویل PR، تمام ده بررسی `npm run validate -- full` را روی
همین مجموعهٔ دقیق و جداگانه اجرا کنید. پوشش اندازه‌گیری‌شدهٔ واحد و گردش‌کار، فهرست
دقیق و import بسته، بدون تماس با API موجود یا بارگذاری dotenv، بررسی می‌شوند. تست‌ها fetch را
شبیه‌سازی و از Web stream مصنوعی استفاده می‌کنند؛ API موجود را فراخوانی نمی‌کنند.

PRهای متمرکز بعدی باید مسیر Next.js، آداپتر صرفاً سروری nonce و جایگزینی هدر درخواست،
نمایش ترجمه، رابط واقعی، SEO و fixture مرورگر را منتشر کنند. پیش از ادغام برنامهٔ
قابل اجرا، گیت کامل پانزده‌بررسی برنامه را اضافه کنید، موفقیت واقعی build و e2e و
visual را ببینید و بررسی‌هایشان را الزامی کنید. قبولی این مرحله شاهد آن نتیجه‌ها
نیست. [سیاست شاخه](branch-protection.fa.md) و [پیش‌شرط بازبینی CodeRabbit](sonarqube.fa.md#پیش-از-درخواست-بازبینی-coderabbit)
همچنان الزامی هستند.
