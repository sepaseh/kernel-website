# Kernel Website localization instructions

Read [README](README.md), [Contributing](CONTRIBUTING.md), the [phase guide](docs/bootstrap.md), [validation manifest](.agents/validation.json) and [snapshot policy](.github/bootstrap-policy.json) before changes.

This standalone TypeScript localization phase owns pure wire definitions, form-input helpers, API-origin validation, public-settings language loading and complete local catalogs. Its twenty-two production modules have only local production imports. Read [localization](docs/localization.md) before message changes. Keep the source closure explicit; no runtime dependencies, React/Next implementation, UI, browser fixtures or deployment are included. applicationReady remains false. Never import another checkout or add workspaces/local-package links.

Keep one flat 107-key string catalog per registered language under src/i18n/catalog-data/locales. Preserve genuine translations, ICU {variable} names and intentional newlines in all ten languages; no nested common objects, English fallback spreads or duplicate aliases. Data imports are erased local types only. The plain local registry does not select language or infer direction; rendering adapters and their owner tests arrive with runnable source.

Preserve API-owned active-language and direction authority, no-store settings reads, safe origins, password whitespace and normalized mobile digits. Use synthetic tests; never load real dotenv, credentials, DB/storage or existing services. Vitest uses Node and envDir:false.

The canonical full phase gate is npm run validate -- full after npm ci. It must pass on the exact isolated snapshot before an authorized commit, push or PR handoff. Never substitute primary-checkout results, omit failures or fabricate coverage. Keep each PR at 100 or fewer GitHub changed-file entries.

Every PR, including drafts, runs that same complete published-phase gate without changed-file filtering. The full profile must contain every required check exactly once and no manual/advisory checks. A focused development profile cannot replace CI. Extend the canonical full profile as source and tests are published; before any runnable-app merge, all fifteen application checks and real build/e2e/visual requirements must be present and pass.

Preserve unrelated work. Git/remote mutations and provider comments require explicit authorization. Use codex/ branches and Conventional Commit titles. Follow the native CI/CodeRabbit/Sonar review process; no custom approval publisher is used. The non-runnable publication requires check, SonarQube Cloud analysis, SonarCloud Code Analysis and CodeRabbit; app build/e2e/visual jobs are not required in this phase. Preserve all other branch protections.

Before requesting an initial CodeRabbit review or re-review, follow the [review-request preflight](docs/sonarqube.md#before-requesting-coderabbit): every required non-CodeRabbit check, from the approved phase-specific set, including scanner and actual Sonar quality gate, must pass for the exact current head, with zero OPEN/unresolved Sonar issues of every severity. Missing evidence blocks requests; a new head invalidates evidence. Exclude only CodeRabbit's own check/approval, respect quotas and do not duplicate an in-flight review.

Assistant instructions are English only. Human docs keep complete English/Persian companions and reciprocal links. A later runnable phase requires the full application build, HTTP/auth integration, browser/CSP, accessibility and reviewed visual checks with a separately installed synthetic API fixture. Before any runnable-app merge, introduce real build/e2e/visual jobs, observe them pass, add them to required checks and expand the full canonical application gate. Current-phase checks do not establish application readiness.
