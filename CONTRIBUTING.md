## Exact-tree gate

Use pinned Node, its bundled npm and Python 3.14.4 in a fresh activated disposable Python environment outside source:

```sh
npm ci
python -m pip install --requirement font-source/requirements.txt
npm run validate -- full
```

Before every authorized commit, push or PR handoff, pass the full profile on an isolated export of the exact proposed tree: eleven checks for the false-marker guidance snapshot; fifteen for runnable application acceptance. Development subsets and primary-checkout results cannot replace it. Every PR, including drafts and docs, runs the complete declared profile without path filtering. Preserve all product analysis/coverage, 90% unit thresholds for four metrics, 80% governance thresholds and real font verification with measured Python coverage. Never fabricate reports, suppress findings or weaken checks. Record first failures, skips, source scope and unavailable evidence; see [testing](docs/testing.md) and [validation](docs/validation.md).

Use owned disposable synthetic resources. False-marker core entries refuse operations; only owned test fixtures may declare readiness for guard tests. Runnable browser evidence uses the explicit independently installed [API fixture](docs/api-fixture.md) and verified browser identity. Never load real dotenv, credentials, existing APIs or operator state. Clean only owned resources. Keep imports inert and readiness before operations.

## Publication and review

Use codex/ branches, Conventional Commit titles and the [PR template](.github/PULL_REQUEST_TEMPLATE.md). Preserve user changes and originals. Commits, pushes, provider messages, merges and external operations require explicit authorization; existing workflow authorization persists. Keep each coherent PR at most 100 GitHub entries including additions, deletions, renames and binaries; a rename is one entry. Prefer near-limit packages without dropping required acceptance.

Keep one website PR open at a time. Prepare later packages locally; after actual authorized merge reconcile real main with the prepared base and rerun the full gate when the tree changes. Create authorized PRs ready for review unless a draft is explicitly requested.

Before CodeRabbit apply the [exact-head preflight](docs/sonarqube.md#before-requesting-coderabbit): successful required non-CodeRabbit checks, scanner and native Sonar quality gate, plus the complete matching all-severity zero-unresolved report. A new head invalidates evidence. Wait at least one hour since both latest request and substantive review, obey longer provider limits and avoid in-flight duplicates. Skipped/conversational replies are not substantive reviews.

Merge only under [ordinary protection](docs/branch-protection.md), current-head approval and resolved conversations. Do not weaken protection to merge. Before runnable merge observe real build/e2e/visual jobs and make them required through an explicitly authorized policy change. Source publication does not authorize operational workflow dispatch or production deployment.

Human docs require complete English/Persian companions and reciprocal links; assistant guidance is English only. Dated QA and archived originals preserve their historical scope and dates, not fresh verification.
