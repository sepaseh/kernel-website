# قالب مرجع سرویس native و درگاه

[English](README.md) · [فارسی](README.fa.md)

این snapshot در مرحلهٔ **delivery-tooling** با `applicationReady:false` همچنان
قابل اجرا نیست. فایل‌ها چیدمان آیندهٔ سرویس و لبهٔ Linux را شرح می‌دهند و آن را
نصب، اجرا یا تأیید نمی‌کنند. سورس فعلی build و سرور برنامه، نسخهٔ native یا نتیجهٔ
smoke استقرار ندارد. نصب [مرجع systemd](systemd/kernel-website.service) شاهد آمادگی
نیست.

چیدمان هدف، نسخهٔ غیرقابل‌بازنویسی و انتخاب current، تنظیم اپراتور و cache نوشتنی
جدا برای هر نسخه را از state متعلق به API جدا می‌کند. مرجع سرویس، حساب کم‌دسترسی
وب‌سایت، preflight و محدودیت فایل‌سیستم و kernel دارد.
[آماده‌سازی artifact](../../scripts/package-release.mjs) و
[preflight](../../scripts/validate-deployment-env.mjs) از نگهبان عمومی مشترک آمادگی
استفاده می‌کنند؛ marker فعلی false عملیات را رد می‌کند. fixture ساختگی آماده فقط
قرارداد ابزار را می‌آزماید و برنامهٔ واقعی را آماده اعلام نمی‌کند. artifact آینده
باید guard و marker مطابق خود و فایل پشتیبان اجرا را همراه داشته باشد.

نمونهٔ [وب‌سایت](website.env.example) و [میزبان](hosts.env.example) جای‌نگهدار عمومی
سورس‌اند. محیط نصب‌شده، رمز یا اثبات اعتماد API به وب‌سایت نیستند. اعتبارنامه و
کلید TLS واقعی بیرون نسخه و سورس بماند. قالب [bootstrap](nginx/bootstrap.conf.template)
و [لبهٔ TLS](nginx/kernel.conf.template) فیلد عمومی بازبینی‌شده را از
[renderer](../../scripts/render-deployment.mjs) می‌گیرند؛ رندر، Nginx نصب‌شده، مالکیت
گواهی، صدور و تمدید ACME یا مرز routing فعال را تأیید نمی‌کند. listener مشترک برای
هر آدرس و پورت یک بلوک رد پیش‌فرض متعلق به اپراتور می‌خواهد؛ نصب بلوک‌های تکراری
default-server روش ترکیب نیست.

فعال‌سازی مجاز آینده باید نخست artifact واقعی برنامه را روی OS، معماری و ابزار
Node مقصد، gateهای الزامی اجرا، fixture API و مرز معتبر میزبان، forwarding، کوکی و
CSP تأیید کند. syntax درگاه مقصد، هدف صریح سلامت، دارایی و فونت و دسترسی واقعی
سرویس بررسی شود. پاسخ تولیدشدهٔ marker نسخه به‌تنهایی build وب‌سایت در حال اجرا را
مشخص نمی‌کند.

تغییر اتمی انتخاب current، لبه و تنظیم مطابق و مالکیت cache هر نسخه بازبینی و سپس
بازگشت به artifact قبلی تأییدشده نشان داده شود. rollback وب‌سایت، migration،
بازیابی داده یا بازگشت قرارداد API انجام نمی‌دهد. این راهنما میزبان، سرویس، گواهی
یا نسخه را تغییر نمی‌دهد. [پذیرش استقرار](../../docs/deployment.fa.md)،
[عملیات](../../docs/release-operations.fa.md) و
[بازبینی امنیت](../../docs/security/reviews.fa.md) را دنبال کنید.
