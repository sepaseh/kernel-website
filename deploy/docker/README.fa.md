# قالب مرجع Docker و TLS

[English](README.md) · [فارسی](README.fa.md)

مرحلهٔ operations در کنار سورس برنامهٔ قابل اجرا و مرجع Docker و TLS، [اجراکنندهٔ محافظت‌شدهٔ smoke دورریختنی Docker](smoke.mjs) دارد. Dockerfile وابستگی کامل ابزارهای ساخت و ورودی مصنوعی صریح ساخت را فراهم می‌کند. `applicationReady:true` و دروازهٔ موفق برنامه ثابت نمی‌کند که موتور، image، stack مربوط به Compose، گواهی تولیدشده یا نشست API در بررسی کانتینر موفق بوده‌اند. این راهنما اجرای موفق Docker ثبت نمی‌کند.

[Dockerfile](Dockerfile)، [مدل Compose](compose.yaml)، [entrypoint وب‌سایت](website-entrypoint.sh)، [اعتبارسنج درگاه](15-validate-configuration.sh) و [قالب Nginx](nginx.conf.template) را به‌عنوان مرجع در انتظار پذیرش عملیاتی بازبینی کنید. build و entrypoint از ابزار مشترک نشانگر عمومی آمادگی می‌خواهند؛ نشانگر false یا نامعتبر باید بدون راه دورزدن رد شود. آمادگی برنامه image یا درگاه را تأیید نمی‌کند. [فایل نمونه](.env.example) جای‌نگهدار عمومی دارد، نه تنظیم اپراتور، اعتبارنامه یا گواهی. dotenv یا کلید واقعی همراه نمی‌شود.

اجراکنندهٔ smoke ابتدا آمادگی و revision عمومی صریح API یعنی `4755d62d14fb9d53cbe9d6246ca9be6bb4a3a7a9` را با سورس پاک و نصب مستقل می‌سنجد. این نسخهٔ API فایل Dockerfile استقرار ندارد؛ بنابراین smoke دستور ساخت fixture متعلق به خود را از سورس عمومی می‌سازد و فایل استقرار مخزن دیگری را قرض نمی‌گیرد. تنها endpoint موتور محلی، پیکربندی Docker تازهٔ متعلق به اجرا، دادهٔ مصنوعی API و راز و فایل TLS تولیدشدهٔ صرفاً آزمایشی، هویت یکتای پروژه و image و builder و عملیات محدود فرزند مستقیم به‌کار می‌روند. آزمون مالک callback مربوط به Docker را تزریق می‌کند و موتور اجرا نمی‌کند. اجرای واقعی smoke جداگانه redirect، دارایی ایستا و فونت، حالت CSP، noindex، کوکی نشست API و هویت نسخه را می‌سنجد و سپس حتی پس از شکست، تمام پاک‌سازی متعلق به خود را تلاش می‌کند.

تفکیک هدف، وب‌سایت و درگاه با upstream مستقل API صریح است؛ مدل عادی Compose سرویس
API یا پایگاه ندارد. مرجع‌ها listener داخلی وب‌سایت، کاربر nonroot وب‌سایت، URL
صریح سلامت، اتصال فقط‌خواندنی گواهی، رد میزبان و TLS ناشناخته و جایگزینی forwarding
معتبر را پیشنهاد می‌کنند. بازرسی ایستا و آزمون محلی پیکربندی، این ویژگی‌ها را در
engine فعال یا حفظ کوکی، CSP و no-store توسط مسیر نصب‌شدهٔ Next.js از این درگاه ثابت نمی‌کند.

[ابزار پاک‌سازی](../../scripts/docker-smoke-cleanup.mjs) با
[عملیات ساختگی تزریقی](../../scripts/docker-smoke-cleanup.test.mjs) آزموده می‌شود و
Docker اجرا نمی‌کند. نام پروژه، image و builder تولیدشده و فایل موقت متعلق به خود
را محدود، با وجود شکست پاک‌سازی مستقل را تلاش و خطا را تجمیع می‌کند. این ابزار
به‌تنهایی حذف منبع engine واقعی را ثابت نمی‌کند؛ [اجراکنندهٔ smoke](smoke.mjs) همان قرارداد پاک‌سازی تحت مالکیت را فراخوانی می‌کند.
prune سراسری یا حذف منبع نامرتبط جای پاک‌سازی متعلق به اجرا نیست؛ image استقرار
نگه‌داشته‌شده چرخهٔ جدا برای rollback دارد.

فعال‌سازی آینده به برنامه و build تأییدشدهٔ جدا، engine و ابزار سازگار، API ساختگی
مستقل، بررسی واقعی TLS، دارایی، CSP و نشست و شاهد پاک‌سازی منبع متعلق به اجرا و
وقفه نیاز دارد. اپراتور پیش از اجرای مجاز باید پورت مقصد، اعتماد میزبان و API،
مالکیت و تمدید گواهی، هویت نسخهٔ غیرقابل‌بازنویسی و بازگشت را بازبینی کند.
[پذیرش استقرار](../../docs/deployment.fa.md)،
[عملیات](../../docs/release-operations.fa.md) و
[اعتبارسنجی](../../docs/validation.fa.md) را ببینید. فهرست مرجع، فرمان دستی `npm run test:docker` را جدا از نمایهٔ کامل پانزده‌بررسی ثبت می‌کند؛ import ماژول آن بی‌اثر می‌ماند.
